# T21: Feedback loop: rejection reason → `evidence.jsonl` → rebuild → changed ranking

## Acceptance gate

```gate
feedback_traceability == 1.0
evidence: status/evidence/T21.json
key: feedback_traceability
```

```bash
echo "no gate command defined for T21 — replace this line with the command that writes status/evidence/T21.json" >&2; exit 1
```

The two blocks do different jobs and both are required. The `bash` block
regenerates `status/evidence/T21.json`; the `gate` block asserts the
number in it against the threshold. Without the first, a stale or hand-written
evidence file passes unchallenged; without the second, a command that exits 0
counts as a gate whatever it measured.

The default command fails on purpose. A task whose measurement is undefined has
not passed its gate — it has not been measured. Replace it as part of the work.

## Scope change — v2 plan, 2026-08-18

Feedback moves **two** things, not one: the weights (through the evidence log
and a rebuild) **and the offer's lifecycle status** (S5). "Not this one because…"
is both an elicitation and a decision point, which is why step 10 is a different
step from step 5 with a different stop rule and a different gate.

What the employer said back is part of the record too — a rejection, a silence
that ran past a stated date, an invitation, an offer, the reason given —
recorded against the application and kept with it.
