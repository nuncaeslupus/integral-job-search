## What this is

A hundred candidates each writing a scraper for the same job board is a
collective waste (owner, 2026-08-18). Connectors should be contributed once and
borrowed by everyone.

**A connector is data, not code** — the owner's decision, and the property the
gate protects. One file per site naming: the site and its locale, list and
detail URL patterns, pagination, and a selector per normalised offer field.
The tool interprets it. Contributing is a pull request; borrowing is copying a
file.

## Why data and not a plugin

Borrowing a plugin means running a stranger's code against your own machine,
where a candidate's whole profile lives. Borrowing a connector file means
running **our** interpreter over **their** selectors, and the worst a malicious
contribution can do is return wrong text. That is the difference between a
community library people can use and one nobody should.

`connector_executes_no_shared_code == 1` is the assertion: no code path
evaluates, imports or shells out to anything a connector file supplies.

## What the format has to survive

- A site changing its markup — a one-field fix any contributor can make.
- Sites needing a login. The candidate's own browser session is the answer
  (step 7); credentials never enter a connector file, and a connector that
  asks for one is invalid.
- Sites that render with JavaScript, which selectors alone cannot reach. Say
  what the format does *not* cover rather than pretending; those are the sites
  that justify a heavier mechanism later.

## Sharing

The library is a public repository of connector files with a version and a
`last_verified` date each. A connector that has not been verified since the site
last changed is stale, and the tool should say so rather than quietly returning
nothing. How contributions are reviewed is out of scope here — the format comes
first, because nothing can be shared until it exists.

## Tests

`test_a_connector_file_cannot_introduce_executable_behaviour` — the gate, as a
test; `test_a_connector_missing_a_required_field_is_rejected_at_load`;
`test_a_site_markup_change_is_a_single_field_edit` — against a recorded fixture
pair, before and after.
