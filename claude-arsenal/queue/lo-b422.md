## Acceptance gate

```gate
elicitation_eval_overlap == 0
evidence: status/evidence/T9.json
key: elicitation_eval_overlap
```

```bash
echo "no gate command defined for T9 — replace this line with the command that writes status/evidence/T9.json" >&2; exit 1
```

The two blocks do different jobs and both are required. The `bash` block
regenerates `status/evidence/T9.json`; the `gate` block asserts the
number in it against the threshold. Without the first, a stale or hand-written
evidence file passes unchallenged; without the second, a command that exits 0
counts as a gate whatever it measured.

The default command fails on purpose. A task whose measurement is undefined has
not passed its gate — it has not been measured. Replace it as part of the work.

## Scope change — v2 plan, 2026-08-18

Stimuli are **fetched live from multiple sources by preference**, chosen using
the constraints already established; the committed corpus is the **fallback**
for when fetching is unavailable, not the primary source
(`status/spec-v2-process.md` §2.3). A corpus is by construction limited and
ageing, and reacting to an advert that could never be yours teaches the tool the
wrong thing.

Two rules protect the measurements, and both are additions to this task:

- Live stimuli **enter the offer store as ordinary offers with status `new`**,
  subject to the same dedup, lifecycle and purge rules. They are not a parallel
  universe of adverts.
- When the corpus is used, stimuli come **only from the elicitation split**.
  `elicitation_eval_overlap == 0` is unchanged and non-negotiable.

**Stimuli are never invented.** An imagined advert reads plausibly and
represents nothing — the failure that put eight wrong cues into the dimension
model with gold examples demonstrating their own error.
