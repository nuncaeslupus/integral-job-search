# T49: trait evidence sufficiency — the gate step 4 never had an owner for

Created 2026-08-18 by owner decision, resolving **D-4**.

## Why this task exists

Step 4's gate is `trait_evidence_sufficiency == 1.0`, and until now no task
measured it. T27 measures `interview_profile_coverage`; T28 measures
`profile_capture_coverage`. Assigning either would have made the documents agree
while leaving the number unowned — the register reads a step's state from the
evidence file its `gate.task` writes, so a task that does not write this metric
cannot make the step truthful.

The owner chose a scoring-only task over widening an existing gate, so the rule
every other step now follows holds here too: **the owner is whoever writes the
number.**

## What it does

Score a trait **only** when its evidence floor is met, and report `insufficient`
otherwise — never refuse, and never guess.

The floor is T27's two-episode / two-occasion rule (see its row in
`status/plan.md` and the step 4 protocol). T27 *carries* that floor as part of
the interview; this task is what *applies* it at scoring time, over whatever
evidence exists by then, from any surface — not only from onboarding.

Read `status/spec-v2-steps.md` step 4 before starting. Two properties from it
matter more than the arithmetic:

- **`insufficient` is a reading, not a failure.** A trait with too little
  evidence is reported as insufficient; the step still completes. Refusing to
  produce a profile because one trait is thin is the behaviour §4 rules out.
- **The floor is never voiced to the candidate.** Nobody is told "you have not
  given me enough examples" — that turns a conversation into a form. It governs
  what may be *scored*, not what may be *said*.

A scored trait below the floor is a stereotype presented as a finding. That is
the harm; the gate exists for it.

## Acceptance gate

Every trait in a derived profile is either scored with its evidence floor met,
or explicitly marked insufficient. No trait is scored on less.

```bash
uv run pytest tests/test_trait_sufficiency.py -q
uv run python -m jobsearch.trait_sufficiency --write-evidence
```

```gate
trait_evidence_sufficiency == 1.0
evidence: status/evidence/T49.json
key: trait_evidence_sufficiency
```

The measurement is a fraction over traits, so a `MINIMUM_TRAITS` floor is
required — 1.0 over one trait is not a measurement.

## Tests

`test_a_trait_below_the_floor_is_insufficient_not_scored` — the harm above;
`test_insufficient_does_not_stop_the_step` — the step still completes, since
refusing is the failure §4 forbids;
`test_the_floor_counts_occasions_not_repetitions` — two mentions in one sitting
are one occasion, which is what "two occasions" is guarding against;
`test_evidence_from_any_surface_counts` — the floor reads the evidence log, not
only onboarding, so continuous capture feeds it;
`test_the_floor_is_never_in_candidate_facing_text`.
