## The reproduction, on disk

Found by the second reader on #305 (D-24), and reproduced there rather than
argued:

1. draft an application — `prepare` writes `cv/generated/<offer>/v1/letter.md`,
   `payload.json` and `approvals.json`;
2. retract the evidence row the approved episode came from;
3. read the files.

`letter.md` still contains the withdrawn story, and `payload.json` still lists it
under `episodes`. Nothing moved them, because `retraction.purge_derived_citations`
scans `{profile, rankings, extractions, annotations}` (`_DERIVED_AREAS`) and
`cv/generated` is in none of them.

## Why this is a divergence and not a nicety

§4.1 requires a retracted fact to be *"suppressed everywhere derived, in the same
turn"* — the one operation whose effect the candidate must be able to see now.

§6.2 and `step-11-application/SKILL.md:118` both say the tool *"stops one step
short of sending: the documents or the text to paste — the candidate presses
send"*. **So the file on disk is the send.** `record_sent` is bookkeeping after
the human sent, not a chokepoint before it.

D-24 closed the half this module can close: after a retraction nothing further
will draft, and nothing will be recorded as sent. It cannot close this half. The
`approval.py` docstring says so now, in *"What this boundary is, and what it is
not"* — that sentence and this task are the same finding.

## What it must not become

**The metric counts unsent versions only.** A generated version named in
`applications/` is out of both the numerator and the denominator: §7 makes that
record immutable, so a withdrawn story surviving in one is the *required*
outcome, not a gate failure — a metric over every version would demand `0` and
forbid the immutability in the same breath. Report the excluded ones under their
own key, `sent_versions_carrying_a_retracted_story`, so the exclusion cannot
quietly hide a growing set, and so a version misclassified as sent shows up as a
number rather than as silence.

**The purge must skip any version already named in `applications/`.** That record
is the only copy of what was actually sent, and §7 makes it immutable — deleting
it would destroy the evidence the candidate answers interview questions from and
would be a worse failure than the one being fixed. `test_retraction_after_send_does_not_rewrite_the_record`
in `tests/test_approval.py` already pins the record itself; this needs the same
rule one level up, over the version directory the record points at.

So the decision the task has to settle is what happens to a *sent* version that
carries a withdrawn story: leave it whole (immutability wins, and the candidate
is told), or leave it whole and mark it. Do not discover this mid-implementation.

**Reuse the join, do not rebuild it.** `approval.retracted_episode_texts` and
`approval._withdrawn_by` already answer "which sentences has a live retraction
withdrawn" over the log, including the kinds a story can be written as and the
normalised shingle match. A second, differently-wrong copy of that join is how
D-24 got its eight fail-open inputs.

**A zero over an empty scan is not a pass.** Record how many generated versions
were examined against a live retraction and write `gate_status: "unmeasured"`
when that is `0`, on the D-24 precedent.

## Tests — write these RED first

`test_a_retraction_purges_the_generated_letter` in `tests/test_retraction.py` —
draft, retract, assert the withdrawn sentence is gone from `letter.md` and from
`payload.json`. **This must fail before any fix.**

`test_a_version_already_recorded_as_sent_is_not_purged` — the immutability
guard; the version's bytes are unchanged, the metric stays `0` because a sent
version is not counted, and the count appears under
`sent_versions_carrying_a_retracted_story`. It must fail if the purge is written
without the `applications/` check.

`test_the_purge_reports_unmeasured_when_no_version_carries_a_retracted_story` —
the denominator.

Every name must contain `purge`, because the gate selects with `-k purge`.

Per `CLAUDE.md`, the fixtures for this gate are written by a session other than
the implementer: it is fail-open and it compares two representations of one
sentence — both triggers.
