## Why this exists

This repository has now shipped a metric whose name promised more than it
counted **five times**:

| | metric | what it actually counted |
|---|---|---|
| T108 | `status_is_asserted` | whether a status is *present*, not which one |
| #323 | `incidental_duplicate_drops` | five wrong drops, framed as noise |
| #318 | `negation_recall_hits_by_mechanism` | `scope` credited on hits `denies` had earned |
| T116 | `robots_adjudications_without_a_competent_second_reader` | read **0** while 19 of 20 rows had none |
| #333 | `verified_gate_defects` | read **0** for a script that ran no gate at all |

Each was caught by a second reader, one at a time, after the code was written.
The read of #334 supplied the rule that catches them **at the point a metric is
named**:

> **A metric named after a *category* of things is satisfiable by there being
> none of them; a metric named after a *wrong outcome* is not.**

`floors_that_do_not_fail_the_gate == 0` is satisfied by there being no floors.
`probes_identical_to_their_fixture == 0` by there being no probes.
`growth_sensitive_evidence_keys == 0` by no keys being classified. Against that,
`bodyless_posts_sent_without_a_content_type == 0` names an event that went
wrong, and cannot be satisfied by absence in the same way — the thing counted is
a failure, not a population.

Four of the twelve metrics #334 made claimable are category-named. That is a
property of the name, checkable without reading the implementation, and today
nothing checks it.

## Scope

- Classify every gate metric declared in `status/plan.md` and in
  `arsenal/tasks/**` as **outcome-named** or **category-named**, and report the
  category-named ones by name.
- The classification must be defensible and **stated**, not a keyword list that
  happens to fit today's board. Write the rule down and cite it per verdict; a
  reader must be able to disagree with a specific call.
- A category-named metric is not automatically wrong — it is a metric that
  **requires a floor**, and the finding is a metric that is category-named *and*
  has no floor asserted. Prefer that as the reported number if the classifier
  can see floors; otherwise report both and say which is the gate.
- Known instances to classify correctly, from #334's read:
  `floors_that_do_not_fail_the_gate` (T115), `probes_identical_to_their_fixture`
  (T117), `growth_sensitive_evidence_keys` (T111), and borderline
  `status_presence_fields_named_as_identity` (T108).

## The obvious trap

A classifier that reports zero because it parsed no metrics is this task's own
subject turned on itself. `metrics_classified_at_least` is a **floor**, and the
task is not done until a mutation removing a metric from the scan makes the
measurement fall rather than the finding disappear.

## Renaming is a two-file change

A metric name lives in `status/plan.md` **and** in the task file's gate block.
`tests/test_plan_v2.py::test_the_committed_plan_and_queue_agree` fails a change
to one and not the other. Any rename this task recommends must say both places.
