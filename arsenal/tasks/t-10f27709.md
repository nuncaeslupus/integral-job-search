Imported from issue #546

## What happens

`sourcing.py:1136` fetches the advert's own page only when the list row **failed** to build an offer:

```python
if offer is None and connector.detail is not None and detail_url:
```

So a connector whose list row is *just* complete enough to build an offer never has its `detail:` block read — however much that block declares. The offer is stored as the teaser.

## Measured on a live run

`jobfluent_es` list rows carry `title`, `company` (the logo's `alt`), a ~113-char teaser `text` and `detail_url`. That builds an offer, so the condition is false. Its `detail:` block declares **seven** fields the list row cannot supply and which were therefore never collected:

```
location_raw  location_country  location_remote
salary_min  salary_max  salary_currency  salary_period
```

Nineteen adverts from one run, re-fetched by hand afterwards:

| | before | after |
|---|---|---|
| body length (median) | 118 chars | 5,651 chars |
| location | absent on all 19 | `Barcelona` on all 19 |
| published salary band | 0 | **5** (42-77k, 35-45k, 60-86k, 94-106k, 118-169k EUR/year) |
| `stack_modernity` extracted | 0/19 | 9/19 |

Those were the **only** salary figures in a 111-offer reachable set — salary coverage across the whole run was zero, and the ranking could not compute `salary_equivalent_total` for a single offer as a direct result.

## Scope today

Derived from the installed connector configs, not from a list of names — connectors whose list block builds an offer *and* whose detail block declares fields the list never carries:

```
jobfluent_es    7 fields unreachable
```

One today. The condition admits any future connector with a teaser in its list row, which is a common board shape.

## Why it is invisible

Nothing counts it. `detail_needed` is only incremented inside the same failed-row branch, so a board in this state reports `detail_needed=0, detail_fetched=0` and looks like a board that needed no advert pages. The run reads as a complete success.

## Suggested shape

Fetch the advert page when the connector's `detail:` block declares a field the parsed list row does not supply, rather than when the row fails. `DETAIL_FETCH_CEILING` already bounds the cost and `unopened` already reports what the budget stopped.

## Acceptance gate

```bash
uv run python -m integral.connector_contract --detail-reachability
```

The measurement must be **derived from the connector configs** — for every installed connector, the set of fields its `detail:` block declares minus the set its list block supplies, counted only where the list row builds an offer. A count of named connectors is an enumeration and has no last element; a config-derived set moves when a connector is added. Expected `0`; it is `1` today.
