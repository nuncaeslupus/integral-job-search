# T87: The Excluded section on the page — the candidate sees what was removed and why

## Acceptance gate

```gate
excluded_offers_missing_from_the_page == 0
evidence: status/evidence/T87.json
key: excluded_offers_missing_from_the_page
status-key: gate_status
```

```bash
uv run --extra dev pytest tests/test_presentation.py -q
uv run --extra dev python -m integral.presentation
```

`src/integral/presentation.py` must write `status/evidence/T87.json`. It already
writes `status/evidence/T44.json` for another task — add this record beside it
rather than replacing it, so both gates keep reading. **A gate must never name a
file no module produces** — the file not existing yet is the honest state of an
unstarted task; the file existing but empty of this metric is not.

The `bash` block regenerates it; the `gate` block asserts the number in it.

## Why

T79 finished half the sentence. `rank()` now removes every `FAIL` before the
frontier and emits an `excluded` list carrying each exclusion's `reason` and the
advert's own `quote` — but `presentation.render()` does not read that list, so
the page the candidate actually sees says nothing about it. From where they sit,
an offer that was barred and an offer that was never found look identical.

That is precisely D-18's rule unmet: quietly dropping four of nine looks the same
as nine having been found, and the candidate then wonders why so little came
back. It is also the reason the eligibility gate carries a quote at all. A
verdict the candidate cannot trace to a sentence in the advert is one they cannot
dispute — and a false `FAIL` is invisible by construction, because an excluded
job is one they never see. The quote is the only thing that makes the exclusion
auditable by the person it was made about, and it is worth nothing while it sits
in a JSON file no page reads.

`FLAG` has the same gap on the card side: `ranking["flagged"]` names the offers,
and spec §5.4 says "ranked, marked, and the human is the tiebreaker" — the
*marked* half is the card's, and T79 did not do it.

## What it must not become

**Do not let the model write the section.** D-17's lesson governs here as it does
on the offer card: render the template from `ranking["excluded"]`, do not let
prose be assembled around it. The `quote` is a verbatim slice of the advert, and
T77's provenance rule does not stop applying because the text reached a page.

**Do not re-derive the verdict.** `presentation.py` is not on T78's boundary
table, but the principle it protects is the same one: the page shows what the
gate decided. It must never call `eligibility` itself, and it must never read
`offer.eligibility` or `offer.language_requirement` — a page that recomputes a
verdict is a second gate nobody gated.

**A zero-violation count over an empty input set is not a pass.** The gate counts
excluded offers that reached the ranking and did not reach the page, and nothing
counted is also zero — so the evidence record must carry
`excluded_offers_missing_from_the_page_evaluated` (exclusions actually rendered)
and write `gate_status: "unmeasured"` whenever that count is `0`, with the metric
at `-1`. `gate_evidence.py` reads `status-key` before it reads the metric and
exits **3** on `unmeasured`: the check ran, and what it found is that this cannot
be scored yet. Assert the denominator, and plant a negative control — drop one
exclusion from the page and the count has to rise.

## Tests — write these RED first

`test_an_excluded_offer_appears_on_the_page_with_its_quote` in
`tests/test_presentation.py`.

`test_an_excluded_offer_gets_no_card` — it is listed as excluded, not rendered as
an offer the candidate might take.

`test_a_flagged_offer_is_carded_with_its_marker` — kept, and visibly marked.

`test_the_page_reports_the_excluded_count_even_when_the_list_is_long` — the count
is stated, never implied by the length of a truncated list. `DEFAULT_LIMIT`
already truncates cards; an exclusion list silently cut to the same limit would
reintroduce the exact under-reporting this task exists to close.

`test_the_gate_does_not_pass_on_an_empty_input_set` — assert
`excluded_offers_missing_from_the_page_evaluated` is written and non-zero.
