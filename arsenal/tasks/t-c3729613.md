Imported from issue #541

## What happens

`source()` spends one `OFFER_CEILING` (50) across every board it is handed, and
`packages_for()` deliberately returns the candidate's own country first so that
"the candidate's own market spends `OFFER_CEILING` first". The two together mean
the domestic boards empty the budget before a single `GLOBAL` board is asked.

Measured on a live run, 2026-09-22, for an ES candidate whose reach includes
`remote` and `cross_border_remote_employer` (so T167's gate does **not** exclude
them):

| round | boards that answered | added | every later board |
|---|---|---|---|
| 1 | talent_es 32, jobfluent_es 18 | 50 | `skipped: "the run reached its offer ceiling"` |
| 2 | talent_es 36, tecnoempleo_es 14 | 50 | same |

greenhouse, lever, ashby, workable, rippling and the nine other `GLOBAL`
packages were never sent a request in either round. Handed `greenhouse_en`
alone, the same code added **50 offers on the first call** — so the boards work
and nothing but the budget order was stopping them.

T167 fixed *selection* of GLOBAL boards. It did not fix *reach*: they are
selected, ordered last, and starved.

## Why it matters beyond one candidate

Any candidate in a country with a productive domestic board gets a search that
silently never leaves that country. The run reports it — `NOT asked, after the
ceiling:` — but a board that is never asked cannot be compared against, and the
foreign boards are where the pay bands are stated.

## The change

Make the ceiling **per board** rather than per run. The stop rule step 7 states
is *"a per-run offer ceiling, so one badly-scoped query cannot deliver four
hundred adverts nobody will read"* — a per-board cap of the same size satisfies
the intent (no single query floods the tree) while guaranteeing every selected
board is asked. If a per-run total is still wanted, it belongs **above** the
per-board budget, not instead of it, and it must be large enough that the last
board in `packages_for()` order still gets asked.

Whatever the shape, the invariant worth pinning is the one that is false today:

> every board `packages_for()` selects is either asked, or skipped for a reason
> that is not the budget.

## Acceptance gate

```bash
uv run pytest tests/test_sourcing.py -q
uv run python -m integral.repo_gate
```

The gate must include a case where a domestic board can supply more rows than
the whole budget and a `GLOBAL` board is selected after it, asserting the
`GLOBAL` board was **reached**. A count-based assertion is not enough — the
present code already produces a `BoardOutcome` for the starved board, so a
fixture that counts outcomes passes over the defect.
