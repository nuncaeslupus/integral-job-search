`review_reader.read` treats a marker whose *comment author* does not resolve as
"self-review cannot be ruled out" and returns `unresolvable/2` for the **whole
pull request**. That guard is right about the case it was built for — a blank or
decorated author could be the implementer wearing a different spelling, and
`author != pr.author` is vacuously true for an identity that never resolved.

But it is not scoped to that marker. One comment by `github-actions[bot]`,
`dependabot[bot]` or any other name outside GitHub's login grammar sets the
verdict for every other comment on the PR, so a genuine second reader's
`verdict=CLEAR` on the head commit is discarded — **in either comment order**,
because the guard fires on the presence of the unresolvable author and not on
where it sits. Found by the second reader on #408 (F3).

This fails **closed**: it refuses a merge rather than allowing one, which is why
it did not block that PR. It is still wrong. A bot whose display name this
module cannot parse should not be able to veto a human review, and the shape —
one unparseable row deciding the answer for a set — is the same shape as
`is_docs_only`'s empty-list refusal, which was resolved deliberately and written
down. This one was resolved by accident.

## The question this task has to settle

**It is open, and this file does not answer it.** Both answers are defensible and
the task is to choose one, argue it from CLAUDE.md § *The review half of
`merge-policy` is a second session, not a bot*, and write the argument down:

1. **Skip the unresolvable marker and keep counting the others.** A marker that
   names nobody is not a report, so it should be discarded the way a comment
   with no marker at all already is — and a resolvable second reader's clearance
   on the head still clears it. The risk: an author *can* appear as an
   unresolvable spelling of themselves, so a PR could be cleared by a marker the
   implementer wrote, if some other comment happens to resolve.

2. **Refuse wholesale, and say so.** If any marker on the PR names nobody, self
   review cannot be ruled out anywhere on it, so `unresolvable/2` stands — but
   the reason string must name the unresolvable author and state plainly that a
   head-bound clearance was set aside, so the human reading exit 2 knows to fix
   the capture rather than to hunt for a review that is already there.

Whichever is chosen, the losing branch's risk is recorded in the module docstring
next to the choice, in the idiom the five #408 rounds established.

## What the metric counts

`unresolvable_marker_authors_with_an_unrecorded_effect` is the number of
constructed states pairing an unresolvable marker author with a genuine
second reader's head-bound clearance — **in both comment orders** — whose
outcome is not the one the chosen rule requires *or* whose `Verdict.reason`
does not name the unresolvable author and say what became of the clearance.
The disjunction is load-bearing and was a conjunction until the second reader
on #408 caught it: under `and`, the "refuse wholesale" answer scores zero with
no change at all, because today's code already returns `unresolvable/2`. A gate
satisfied by doing nothing is the defect this repository keeps meeting, and it
had reached the task filed to record one.
It is zero under either answer above and non-zero under today's behaviour,
which discards the clearance silently. The states evaluated are the
denominator, asserted as a floor in the `naming.MINIMUM_SCANNED` style (T100)
so a control list that shrank to nothing cannot score a serene zero.
