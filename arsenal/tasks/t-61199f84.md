`open_task_pr.sh` cannot open a pull request in this repository, and bundle
v3.2.0 did not fix it — the v3.1.14 changelog only says it did
(`claude-arsenal#336`). The script runs the host gate **twice**, at `:227` before
the task file is archived and at `:627` after. `make evidence` fails on drift, so
the committed evidence would have to hold two values at once:

    pre-archive = 615    post-archive = 614

No value satisfies both, the script never reaches `gh pr create`, and every PR
since #257 has been opened by hand.

**The obvious fix is wrong.** Counting `arsenal/tasks/_history/` would make the
number archive-invariant and immediately break `old_name_references == 0`:
`naming.py`'s own allowlist docstring explains that archived rows legitimately
carry the old name, and that a past task file is a ledger entry nobody may edit.
Scanning them would report violations that must never be repaired.

**The real fault is that `files_scanned` is committed as an exact value at all.**
It is a *denominator* — how many files the check looked at — not a measurement of
anything about the code. It moves whenever any tracked file is added, which is
why the CLAUDE.md section about it has been rewritten three times and was wrong
twice.

The denominator still has a job: it is what stops a clean zero resting on an
empty scan, the "dishonest zero" that docstring was written about. A **floor**
does that job and does not move — and this repository already has the pattern,
in `retraction.py`:

```python
if measured["derived_files_scanned"] < MINIMUM_SCANNED:
```

So: assert `files_scanned >= <floor>`, keep `old_name_references == 0` exact, and
the archive stops mattering. Pick the floor from the current count with room to
shrink, and say in a comment that it is a floor rather than a census.

Do not silently drop `files_scanned` from the evidence file — a reader comparing
two evidence files needs to see the number, it just must not be a drift trigger.

## Acceptance gate

```bash
uv run --extra dev pytest tests/test_naming.py -q
uv run --extra dev python -m integral.naming
```

Then the property the whole task exists for — the measurement must not move when
a task file is archived:

```bash
uv run --extra dev python -c "
import shutil, subprocess
from pathlib import Path
from integral.naming import measure
live = sorted(Path('arsenal/tasks').glob('t-*.md'))[0]
hist = Path('arsenal/tasks/_history') / live.name
before = measure()
hist.parent.mkdir(exist_ok=True)
shutil.move(str(live), str(hist))
try:
    after = measure()
finally:
    shutil.move(str(hist), str(live))
for key in ('old_name_references', 'old_package_references', 'old_repository_references'):
    assert before[key] == after[key], (key, before[key], after[key])
# The denominator is allowed to move — that is the point. What must hold on
# both sides of the archive is the floor, which is what replaces the exact value.
from integral.naming import MINIMUM_SCANNED
for m, side in ((before, 'pre-archive'), (after, 'post-archive')):
    assert m['files_scanned'] >= MINIMUM_SCANNED, (side, m['files_scanned'])
print('archive-invariant:', {k: before[k] for k in ('old_name_references',)})
"
```
