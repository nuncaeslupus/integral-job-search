# D-25: The simulation prompt's parity table is argued, never measured

## Acceptance gate

```gate
simulation_stages_unverified == 0
evidence: status/evidence/D-25.json
key: simulation_stages_unverified
status-key: gate_status
```

```bash
uv run --extra dev pytest tests/test_simulation_parity.py -q
uv run --extra dev python -m integral.simulation_parity
```

`src/integral/simulation_parity.py` does not exist yet and must write
`status/evidence/D-25.json`. It reads §2 of `docs/simulation-prompt.md` and the
recorded observations (below), and counts stages whose verdict no observation
backs.

## Why

`docs/simulation-prompt.md` §2 classifies all thirteen stages — eight faithful,
four degraded, one manual — and the file says plainly that **nobody has run §3 in
an actual chat**. Every verdict in that table was derived by reading the step
skills and reasoning about what prose can carry. None was observed.

That is this repository's own named failure: a claim about behaviour, published,
with no measurement behind it. It shipped anyway because the alternative was
withholding a usable artifact indefinitely, and because the file states the gap
rather than hiding it — the D-12 and D-23 precedent, where the mechanism ships
and the accuracy waits.

**The reasoning that produced the table has a known error rate.** The PR that
introduced it (#252) took twenty-two review findings over six rounds. Two were
mechanisms asserted without reading the function they described; one was a
privacy guarantee that was true of the tool and false of a chat. A table built
the same way, by the same means, is not evidence about a conversation nobody has
had.

## Precondition — this cannot start early

**The real tool must have been run the actual way first**: a genuine session
through Claude Code, a real candidate, far enough to exercise the stages being
compared. Comparing the simulation against a second act of reasoning about the
tool measures nothing; the whole point is to compare it against the tool's
observed behaviour.

No task tracks that first real run, so this one cannot declare a `deps` edge to
it. `requires: [surface:human]` keeps autonomous selection off it —
`task_select.py` is invoked without `surface:human` by the worker loops — but a
person picking this up should confirm the precondition holds before starting,
because nothing mechanical will.

The `test-mode` skill (S11) is the intended instrument for the real run: it
captures notes about the tool during a live session without disturbing it, which
is exactly the record this task needs.

## What to do

1. Run the real tool far enough to observe each stage's actual behaviour, using
   `test-mode` to capture notes as it goes.
2. Run `docs/simulation-prompt.md` §3 in a plain Claude conversation, as a
   candidate would, with the same inputs where that is possible.
3. For each of the thirteen stages, record an observation: what the tool did,
   what the simulation did, and whether the §2 verdict (`faithful` / `degraded` /
   `manual`) survives contact.
4. Correct §2 where it does not. A verdict that moves is the finding, not a
   failure of the task.
5. Correct §3 where the run shows the prompt misbehaving — a stage it skips, a
   cap it ignores, a rule it breaks.

## What it must not become

**Do not verify a stage by reasoning about it.** That is what produced the table.
An observation is something that happened in a transcript, and the evidence
record must name it.

**Do not quietly downgrade the table to make it pass.** Marking everything
`degraded` would zero the metric and measure nothing. The gate counts stages
whose verdict no observation backs, so an unobserved stage is unverified whatever
its verdict says.

**A zero count over an empty input set is not a pass.** Record
`simulation_stages_evaluated` — stages actually observed — and write
`gate_status: "unmeasured"` whenever it is `0`, `"measured"` otherwise. Thirteen
stages evaluated is the denominator this task exists to raise from zero.

## Tests — write these RED first

`test_every_stage_verdict_cites_an_observation` in
`tests/test_simulation_parity.py`.

`test_a_stage_with_no_observation_counts_as_unverified`.

`test_the_gate_reports_unmeasured_when_nothing_was_observed` — assert
`simulation_stages_evaluated == 0` yields `gate_status: "unmeasured"`.

`test_a_verdict_changed_by_an_observation_is_recorded_not_overwritten` — the
original verdict and the observed one are both retained, because the difference
between them is the measurement.
