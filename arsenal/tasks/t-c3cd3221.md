`connectors/ticjob_es/probe/list.html` is byte-identical to `connectors/ticjob_es/fixture/list.html`.

`src/integral/connector_health.py`'s module docstring names this failure precisely, because the repository has had it before:

> An earlier revision pointed the probe at `fixture/list.html` as well — so the production path compared a string with itself, `silent_connector_failures` could only ever be 0, and the evidence recorded `gate_status: measured` on a module whose entire purpose is detecting parser rot.

That is T72's defect, alive in one package. `status/evidence/T72.json` counts ticjob among `connector_runs_probed` and reports it `healthy` — a healthy verdict from a comparison that cannot fail.

Every other shipped package differs from its fixture (checked by md5 and by content across all of them; the four in #260 were captured live on 2026-09-02 and each shows real turnover).

## Scope

Capture a genuine second read of ticjob's declared query on a later day, cut the way its fixture was cut, and state in `meta.yaml` what differs between the two. Robots first, per `ruled-out.yaml`'s rules, with a negative control.

Then make the identity impossible rather than merely fixed: `connector_health` should count a package whose probe equals its fixture as a **silent failure**, not as healthy. It is the one comparison the module can make with certainty, and it is the one that would have caught both instances.

## Gate

`probes_identical_to_their_fixture == 0`, denominated by every shipped package, with a floor so a scan that finds no packages reports `unmeasured`.
