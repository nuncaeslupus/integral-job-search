`src/integral/liveness.py` must write `status/evidence/T74.json`. It already writes `status/evidence/D-18.json` for another task — add this record beside it rather than replacing it, so both gates keep reading. **A gate must never name a file no module produces** — the file not existing yet is the honest state of an unstarted task; the file existing but empty of this metric is not.

The `bash` block regenerates it; the `gate` block asserts the number in it.

## Why

`liveness.read_response` compares `advert_url` against `final_url` via `same_page` (`liveness.py:120,148`). That catches the **redirect** case and misses the **identity** case: a stored URL like `.../jobs/ciso/#ikerian` fetches 200, renders a listing page of unrelated roles, and the URL never changed — so it reads as the advert and gets scored.

This is the D-18 family: schema validity is not liveness, and now — a live page is not *this* page. Add a fourth reason for `unverified`, not a fourth verdict.

## What it must not become

**Do not add a new verdict.** The three-valued vocabulary is settled; this is one more way to reach `unverified`.

Match on the offer's title against the fetched body, tolerantly — casefold, collapse whitespace. A title match that is too strict turns live adverts into `unverified` and the candidate sees nothing, which is a worse failure than the one being fixed.

**A zero-violation count over an empty input set is not a pass.** The gate counts
violations, and nothing counted is also zero — so the evidence record must carry
`offers_presented_from_a_page_that_is_not_the_advert_evaluated` (offers liveness-checked) and the gate is only meaningful while that count is
non-zero. This is the failure this whole increment is about, turned on its own gates:
a check that reports success over work it did not do. Assert the denominator.
