Filed from #584's second reader (round 2, non-blocking R2-3..R2-5, issuecomment-5897178029). T198 memoised `floor_sweep._analyse` in `_ANALYSES`, keyed on `(name, src_dir.resolve(), _THIS_FILE, _REPO_ROOT, content digest)`.

**R2-3 (fail-open only for a caller that patches between calls).** `_analyse` reads the module's current `MINIMUM_FLOORS_*` values (via `_margin_finding`), and the prose clearance reads `MINIMUM_PROSE_MUTATION_SCENARIOS`; none is in the key. Setting a floor between two same-key calls returns the cached analysis; the reader measured the self-floor finding vanishing. No production path or current test does it. Put those values in the key, or exclude them explicitly with the reason — and pin whichever is chosen.

**R2-4 (latent).** The digest covers `status/evidence/*.json`, while the evidence-path resolver accepts any `_REPO_ROOT/**/*.json`. A traced live run read nothing outside the hashed set, so the key is closed today by coincidence, not by rule. Derive the hashed set from the resolver, or restrict the resolver to what is hashed.

**R2-5 (docs).** The `_ANALYSES` comment still says the key is "never a path", and the `measure` / `_analysed_once` docstrings describe the content-only key.
