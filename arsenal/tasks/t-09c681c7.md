The candidate wrote the missing loop out, in eight steps:

> 1. You try some generic searches, by Google or some direct job sites. 2. You
> see results are not too good, but you found something interesting in two or
> three places. 3. You decide to take those sites and search our connectors
> repo. 4. You don't find a connector for those sites. 5. You ask the user to
> create a directed connector for one or some of those sites. 6. You create the
> connector and add it to the connectors repo. 7. You give the user the results
> you got. 8. Repeat after asking the user in case nothing interesting is found.
> When more and more connectors are available in the repo, it should be much
> easier to find interesting jobs.

Steps 4 through 6 are the whole difference between a fixed library and one that
grows toward the candidate in front of it. Observed instead: three adverts, and
a stop. *"Now it looks as if you have already given up and the process is
finished to you."*

`sourcing_strategy.judge_cycle` already measures exhaustion and
`apply_scope_change` already proposes widening the scope. **Neither can propose
building a connector**, so "exhausted" currently means *this library is
exhausted*, which is a statement about our coverage dressed up as a statement
about the market.

Two things ride along, both from the same note thread and both cheap:

- **Say what a connector is, and that sharing it helps.** The candidate had to
  ask. A one-line explanation plus *"if you share it, the next person searching
  that site gets it for free"* turns a chore into a contribution.
- **A connector built mid-session needs a declared home before it is uploaded.**
  Right now there is nowhere for it to live between "written" and "merged into
  `connectors/`", and the candidate asked for the rule.

## Acceptance gate

```bash
uv run --extra dev pytest tests/test_sourcing_connector_gap.py -q
uv run --extra dev python -m integral.sourcing_cycles
```

- `test_an_exhausted_cycle_names_a_site_it_cannot_read` — exhaustion cites a
  concrete unreachable board, never a bare "no more results".
- `test_the_proposal_says_what_a_connector_is_and_that_sharing_helps`
- `test_a_connector_written_mid_session_has_a_home_before_it_is_uploaded`
- `test_a_library_miss_is_never_reported_as_a_market_miss` — the distinction the
  whole task exists for.
