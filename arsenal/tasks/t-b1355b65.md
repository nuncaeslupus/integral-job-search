Owner check after the test session of 2026-08-20: of the seven offers sourced, the two jobtoday.com
listings return **403** and every tablondeanuncios.com listing reads **"Puesto ocupado"**. Not one was
a live vacancy. They were surfaced by a generic `WebSearch` over indexed pages, which is exactly the
failure mode: a search index outlives the advert.

Owner's rule, to encode: **real searches are run inside the portals**; a generic `WebSearch` is for
*discovering new portals*, not for collecting adverts.

What this needs:
- sourcing must fetch the detail URL and treat 403 / "puesto ocupado" / "oferta cerrada" as expiry,
  not as an offer;
- `jobsearch.freshness` already exists — wire it into the sourcing path and mark dead ones expired;
- `step-07-sourcing` prose must forbid presenting a search-index result as a live offer.

Addressed in: `step-07-sourcing`, `src/jobsearch/freshness.py`, `src/jobsearch/offers.py`.
