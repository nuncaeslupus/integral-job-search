## Observed

`python -m integral.prior_documents --id <handle>` on a profile whose applications predate the current pipeline lists every version under SKIPPED and reads nothing, so step 11's "look at what already exists" has no input.

Three causes, measured on one profile with 60 stored versions across 15 offers:

- 49 versions carry a legacy `manifest.json` (`claims: [{claim, source}]` plus keys such as `generated_at`, `note`, `omitted`, `accent`, `posting_url`, `flagged`, `left_out`, `changed_from_v1`). `_read_version` validates against the strict `integral.generate.Manifest`, which rejects them.
- 11 versions have no `manifest.json` at all.
- 46 versions have no `*.md` document; they hold `cv.json` / `letter.json` plus HTML and PDF from the earlier generator. `_read_version` requires a `.md` and skips with "no document … is present".

## Wanted

The digest reads a legacy package as a legacy package: documents from `cv.json` / `letter.json` (or `*.md` when present, e.g. a form `answer.md`), claims from the legacy manifest when there is one, and marks the version as legacy with episode counts UNDETERMINED rather than zero.

Do not rewrite stored packages into the current schema. A current claim is an exact line of a `.md` with an `entry_index` into `cv/master.json`; converting would invent traceability for documents already sent, and step 11 never overwrites a version.

## Gate

Fixtures built from the three shapes above (legacy manifest, no manifest, no Markdown); `versions_skipped_for_legacy_shape == 0`, with the count of versions read committed as a floor.
