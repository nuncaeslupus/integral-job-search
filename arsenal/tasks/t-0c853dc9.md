## Acceptance gate

```gate
status_presence_fields_named_as_identity == 0
evidence: status/evidence/T108.json
key: status_presence_fields_named_as_identity
```

Transcribed from `status/plan.md`'s row for this task, which declared this
metric before the task was imported. The name is the plan's, not a new one:
inventing a second name for a declared metric is a mistake this repository has
made four times, and `test_the_committed_plan_and_queue_agree` fails it.
Imported from issue #296

Two independent reviews, on #286 and #290, read `status_is_asserted: true` as claiming the gate's status **is** the string `asserted`, and both proposed setting it to `false` because the underlying evidence says `gate_status: "measured"`.

Both were rejected, because the field means something else — `task_gate.py:135-139`:

```python
status_key = fields.get("status-key")
asserted = False
if status_key:
    status_found, status = _dig(data, status_key)
    asserted = status_found and isinstance(status, str) and bool(status.strip())
```

It records that a status **is asserted somewhere** — that the declared `status-key` resolves to a non-empty string. `"measured"` satisfies it. What it guards against is a gate block declaring a `status-key` over an evidence file that asserts nothing there.

## Why this is worth a change rather than two rejections

The same misreading twice, by readers coming to the file cold, is evidence about the name and not about the readers. The value is right and the name invites the wrong conclusion — and the suggested "fix" both times would have broken CI (`D12.json` is generated) and made the task's own gate unrecordable (`recordable` is `value_is_numeric or status_is_asserted`).

There is a second cost: a human skimming `D12.json` for a gate that is genuinely misconfigured has to know this distinction to read the file at all.

## Scope

Rename the field and its `Reading` attribute to something that says *presence*, not *identity* — `status_key_resolves`, `status_is_recorded`, or similar. Small and mechanical, but it touches:

- `src/integral/task_gate.py` — the dataclass field, the `recordable` property, the emitted key
- `status/evidence/D12.json` — regenerated, not hand-edited
- any test asserting the key by name

Do it as one rename with no behaviour change, so the diff is legible and the regenerated evidence is the only data change.
