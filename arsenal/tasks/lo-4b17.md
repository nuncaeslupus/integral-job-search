## Acceptance gate

```gate
extraction_negation_recall >= 0.80
evidence: status/evidence/T16.json
key: extraction_negation_recall
status-key: negation_status
```

```bash
uv run --extra dev pytest tests/test_negation.py -q
uv run --extra dev python -m integral.extraction --negation
```

The `bash` block regenerates `status/evidence/T16.json`; the `gate` block
asserts the number in it. **`status-key` is what makes this task honest while it
waits**: until the corpus carries negated labels, `integral.extraction` records
`extraction_negation_recall: null` beside `negation_status: "unmeasured"`, and
`gate_evidence.py` exits 3 — "the check ran, and what it found is that this
cannot be scored yet". That is not a pass and not a fail, and it is the state
this task is in on the day it is filed.

## Why this is its own task

Split out of T16 (`lo-bd02`) on 2026-08-23, on the owner's decision, following
the shape **D-12 (`t-e1ca8374`, #83)** used to split T15 into T15 + T56
(`lo-6f53`). T16 fixed negation *scope* — two adverts in the corpus had a
negator reaching across a sentence end and a line break to invert a cue in the
next clause — and can show that with `negation_scope_leaks == 0` and
`negation_window_only_count == 2`. It cannot show the negation is **accurate**,
because accuracy needs labels that do not exist: `status/evidence/T16.json`
records **2** negated labels, both on `tecnoempleo-98201f7d82b073d32d45`,
against a floor of 10.

T56 waits on the same two corpus tasks for the same reason. One round of
labelling unblocks both.

## What it must not become

D-2 (`lo-77a6`)'s three requirements are carried here unchanged:

1. **Score only what a person decided.** Negated `Label` rows whose `source` is
   `human`, `confirmed` or `edited`. Never `corpus/labelled/suggestions.json`,
   never `extraction.gold`.
2. **Refuse to emit the number below the label floor**, naming the shortfall in
   the evidence file rather than averaging two rows.
3. **Emit `n` beside the score** — `negated_label_count` already is that `n`.

**Do not resolve this by relaxing the floor**, and do not count a denial the cue
set matched literally (`sin guardias`, `no on-call`) as a negation the scope
rule recovered. Those are two different mechanisms reaching the same class, and
conflating them makes recall look solved while `negatable` cues stay untested —
`travel_requirement` on the one labelled advert is exactly that case today.

## Tests

`test_negated_labels_are_recovered` in `tests/test_negation.py` — recall ≥ 0.80
over the negated subset, once the subset can carry a number.

`test_recall_is_refused_while_the_corpus_cannot_carry_it` in the same file is
this task's placeholder, and lives there now: it asserts the *refusal* — null,
`unmeasured`, count below floor. `negation_audit` raises once the corpus
passes the floor, so that test is what fails to announce this task is workable.
