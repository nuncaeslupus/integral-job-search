# Payload: t-6e73179f — `second_reader.allows()` fails open when handed a URL

**Gate**: no reader in this repository answers `True` to a target it did not
adjudicate. A value that is not the shape the parameter names is refused or
raised on, never silently allowed.

## Tests

- `test_a_full_url_is_not_silently_allowed` in `tests/test_second_reader.py`
  — `allows(text, agent, "https://es.talent.com/ajax/x")` against a file whose `*`
  group disallows `/ajax/`. Today this returns `True`; it must not.
- `test_the_two_readers_agree_on_the_same_target` in `tests/test_second_reader.py`
  — for each of a set of (file, path) pairs carrying both allows and disallows,
  `integral.robots.Robots().allows(<absolute url>)` and
  `second_reader.allows(text, agent, <path>)` return the same verdict. Derived from the
  pairs, not enumerated per case.
- `test_every_reader_rejects_a_target_of_the_wrong_shape` in `tests/test_second_reader.py`
  — derived over the readers `connector_policy` can install (`DEFAULT_SECOND_READER` and
  any sibling), so a reader added later is covered without anyone remembering to. Each is
  handed a target of the *other* reader's convention and must not answer `True`.

## References

- Code: `src/integral/second_reader.py` — `allows(text, agent, target)`. `target` is a
  **path**; a value beginning `https://` matches no rule and falls through to the
  permissive default.
- Code: `src/integral/robots.py` — `Robots().allows(url)` takes a **full URL**. The
  opposite convention, in the sibling module, with no type or name distinguishing them.
- Code: `src/integral/connector_policy.py` — `DEFAULT_SECOND_READER` is
  `integral.second_reader` since T120, so this is the reader every adjudication now runs
  through.
- Ledger: `connectors/robots-adjudications.yaml` — every row with
  `standing: two_parsers_agreed` was produced through this API. None is known wrong; the
  point is that a wrong one would not have shown.

## Context

Found on T194 (#520) while re-deriving `es.talent.com`'s adjudication independently of
the connector's own `connector.yaml`, which is what the brief asked for. The
re-derivation **appeared to refute a correct row** — all four targets returned `True`,
including the two negative controls the ledger requires — because full URLs were passed
to a parameter that wants paths. The row was right; the call was wrong; nothing said so.

Both directions of that are bad. The one that cost this session an hour is the false
refutation. The one that matters is the other: a session adjudicating a *new* board this
way records `two_parsers_agreed` over a reader that refused nothing, which is precisely
the "agreement with a parser that cannot disagree" the `connector-new` skill and
`ruled-out.yaml`'s header both warn about — reached by a different route, and a
fail-open one.

A fix that only renames the parameter is not a fix. The check must be that a target of
the wrong shape cannot resolve to `True`.
