**Gate**: the skill states no count of the evidence keys a new package moves. It states
the rule for deciding whether a moved key is truthful, which does not go stale.

## Context

Found on T194 (#520). Seven committed counts moved, not two, and every one was truthful:
`+1` for the package on four keys, `+3` on two more for the reason above, and the
provenance census. The skill says a third is a finding, so the session spent real time
proving six non-findings before trusting a green run.

That is the cost worth naming. A stale number in a skill does not merely fail to help —
it manufactures doubt about correct work, and the session either pays to refute it or,
worse, edits something to make the count match. The remedy is not a bigger number.
**A census in prose has no last element**, exactly as this repo's CLAUDE.md says of test
enumerations; the skill should say how to tell a truthful move from a real finding and
name no count at all.

Small task, and deliberately so — `priority: 10` (S). It is one section of one file plus
the check that stops the number coming back.
