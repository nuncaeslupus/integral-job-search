### Finding
`source()`/`source_every_phrase()` require a `fetch: Callable[[ListRequest], Response]`, but no module implements one over the network (only fixture/capture fetchers exist), and the skills say `fetch=<a live fetcher>`. The agent therefore writes ad-hoc HTTP code each session, so User-Agent, timeout, redirect handling, body-size cap, POST body/headers and charset decoding are unpinned; `decode_body()` and the connector `charset` field are never called outside their own probes, and robots is only checked for the pre-redirect URL.

### Evidence
grep for urlopen/requests in src/: only robots.py:134, canonical_ad.py:123, connector_exchange.py:208 (none take a ListRequest). `grep -rn 'decode_body(' src tools` returns only probe lines in connectors.py:4953-5039. sourcing._main only writes evidence. Skill text refers to 'the plain fetch' without defining it.

### Suggested direction
Ship one `live_fetch(robots)` in src (honest UA, timeout, size cap, https-only + robots-checked redirects as in canonical_ad._GuardedRedirects, `decode_body(raw, connector.charset)`), plus a CLI (`python -m integral.sourcing run --handle …`) so the step is a command, not code the agent writes.
