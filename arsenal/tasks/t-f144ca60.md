Found by the second reader on #445 (T144, finding F5), and wider than that
finding says.

`connectors/greenhouse_en` maps `text: content`, and boards-api.greenhouse.io
serves `content` as **HTML-escaped HTML** (`&lt;p&gt;&lt;strong&gt;Summary…&amp;nbsp;`).
The candidate reads markup. `dedup.normalise_for_comparison` turns the tags into
`lt p gt` tokens, so the same advert read escaped and read clean scores a
Jaccard of 0.34–0.46. That still clears `SIMILARITY_THRESHOLD = 0.25`, but it
eats most of T75's employer-vs-aggregator margin, over about 6,000 postings per
run.

**Six other connectors carry the same defect, one layer shallower.** Measured
2026-09-10 on `main` at 912ea8f (#445 merged) by building an offer from every
connector's fixture: 13 of 75 carry markup in `text`.

| connector | route | what `text` holds |
|---|---|---|
| greenhouse_en | JSON `content` | escaped HTML, two layers |
| workable_en | JSON `description` | raw HTML (`<p>…`) |
| rippling_en | JSON, embedded `__NEXT_DATA__`, detail | raw HTML with inline styles |
| himalayas_en | JSON `description` | raw HTML (`<p><strong>…`) |
| workingnomads_en | JSON `description` | raw HTML |
| weworkremotely_en | CSS `description`, list page only | the RSS body, which holds escaped HTML |
| getmanfred_es | JSON, embedded | Markdown with inline `<u>` |

lever_en is clean: since #445's round 2 it reads `text` from the advert page's
`div.content`, through the CSS route.

## Design (owner-approved 2026-09-10)

- **Two `take:` members, not one.** `html_text` reads the value as HTML and
  keeps its text, via the existing `parse_html` and `Node.text_content`, which
  is the code an HTML connector already uses on an element. So a JSON field
  and a CSS field reading the same markup yield byte-identical text.
  `escaped_html_text` runs `html.unescape` **once**, then does `html_text`.
  A single "unescape, then strip" member was rejected: on raw HTML it turns an
  escaped literal (`experience with &lt;canvas&gt;`) into a tag, and the word
  disappears from a tech advert.
- **Fail closed**, like the other members: when no text survives, the field is
  left empty and never gets the unparsed string back.
- **JSON fields gain an optional long form.** A `JsonSource.fields` value is
  either a path string (unchanged, so no connector needs rewriting) or
  `{path: …, take: …}`. `last_text_node` is refused on a JSON field when the
  connector loads: it is a markup-tree operation and a JSON string has no
  tree.
- **Every connector is in scope, not only greenhouse.** Apply the member to
  greenhouse, workable, rippling, himalayas, workingnomads and
  weworkremotely's list `text`.
  getmanfred's Markdown is the one judgement call: either `html_text` (it drops
  the `<u>` and keeps the Markdown) or a reviewed exemption. Whichever it is,
  write the reason down.

**Tension to answer in the PR, not ignore:** `Node.raw_text`'s docstring
requires `Offer.text` to be what the board published, byte for byte. That rule
protects a JSON value from being reflowed by accident. A declared `take:` is a
deliberate transform, and it is the same one every HTML connector already
applies. Evidence spans are offsets into the built `Offer.text`, so they stay
consistent.

## Tests

- `test_no_fixture_offer_text_carries_markup`: every connector's fixture,
  built the way sourcing builds it (list merged with detail, detail winning),
  yields no offer whose text carries an HTML tag or character reference. The
  population is discovered from `connectors/`, never listed, and floored at a
  literal.
- `test_escaped_and_raw_markup_read_to_the_same_text`: for **every** fixture
  value read through `html_text`, escaping the source and reading it through
  `escaped_html_text` gives identical text, so the same advert gets identical
  dedup tokens from either encoding. The rule is derived from the fixtures, not
  from a list.
- `test_markup_take_contracts`: the second session's table, below.
- `test_last_text_node_is_refused_on_a_json_field`: refused when the connector
  loads.

**The contract table is written by a session other than the implementer**
(CLAUDE.md, "Fixtures for a correctness-critical gate are written by a second
session"). It derives each case from the WHATWG HTML spec's character-reference
and tokenisation rules and from Greenhouse's Job Board API docs, before opening
the implementation. At minimum it covers: a double-escaped entity
(`&amp;amp;`), `&nbsp;`, numeric references, an escaped literal `<canvas>`
surviving as text on each route, block elements not welding words together,
`<script>`/`<style>` bodies, and markup that yields no text (fail-closed).
Every accepted case is committed before merge.
