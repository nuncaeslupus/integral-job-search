A paragraph that ends in one or two words wastes a line and reads as carelessness.
On a two-page CV it is also the difference between fitting and not. This was
measured by hand for a live application on 2026-09-07 (`widows.py`, in that
candidate's `cv/generated/<offer>/v12/`) and cut nine short last lines to zero
across a CV and a letter; this task is to make it part of the render (T142).

**What it measures.** Words are grouped into lines by vertical position; a line is
a widow when the line above it runs the full column, nothing follows it inside the
block, and it is under a threshold of the column width. It reports the page, the
ratio and the text, and exits non-zero when it finds any — so a render can be
gated on it rather than eyeballed.

**Two things the first version got wrong, and each is a contract**

1. **A grid row is not a line.** Three columns of a `display: flex` grid share a
   vertical position, so a row spans the page and every cell's last line looked
   like a widow. Nineteen findings, six real. Contract: words in a row are split
   where the horizontal gap says a new column began, and each run measured alone.
2. **A section heading is not a paragraph.** `EXPERIENCE` follows a full body line
   and is followed by a gap, which is the widow shape exactly. Contract: a line set
   entirely in capitals is not reported.

**What it must record, because it is the part that gets used wrong.** Shortening a
paragraph by *fewer* words than its last line carries makes the widow shorter, not
gone — cutting two words from a three-word widow leaves one, which is worse. The
report has to say how many words the line holds, so the fix is a quantity and not
a guess.

**Why the measurement is behavioural.** The check runs against a rendered PDF, not
against the source text: line breaking is the renderer's decision and no amount of
reading the JSON predicts it. `widow_defects` is the number of widows in the CV
and the letter this repository generates for a fixture offer, and it is zero.
