The metric already exists and already reads **3**. T120 wrote it, and this task
is what makes it fall — the gate is not a new measurement, it is the one T120
committed with nobody assigned to it.

## The defect

`integral.robots` — the matcher `CLAUDE.md` tells every session to adjudicate a
real board with — answers **ALLOW** for three paths RFC 9309 refuses. They are
one bug, not three:

```
User-agent: *                 request                        case
Disallow: /foo/bar?baz=https%3A%2F%2Ffoo.bar
                              /foo/bar?baz=https://foo.bar   31
Disallow: /s?q=a%26b          /s?q=a&b                       50
Disallow: /s?q=a%3Db          /s?q=a=b                       51
```

§2.2.2 states its canonicalisation over a set rather than over an example:
octets "outside the range of the US-ASCII coded character set, and those in the
reserved range defined by RFC3986, MUST be percent-encoded ... prior to
comparison" (RECOLLECTED). `:`, `/`, `&` and `=` are all in RFC 3986's reserved
range, so each of the three rules above and its request are two spellings of one
URI, and each rule refuses. The section's example table (row two) *illustrates*
the requirement with `:` and `/`; it does not bound it.

The cause is one constant. `robots.py`'s `_CHUNK_SAFE = "/:@!&'()+,;=?~-._"`
carries `:`, `/`, `&` and `=` — and `@`, `!`, `(`, `)`, `+`, `,`, `;` besides —
so it leaves them unencoded everywhere, including as data inside a query value,
and the rule and the request never compare equal.

**It is fail-open**, in the matcher that decides real fetches. The reserved
octets `_CHUNK_SAFE` currently exempts and no committed case yet exercises are
the untested remainder of the same hole, not a separate one.

## How it was found, and why the finding is committed rather than fixed

T120 replaced the *second* reader and, in doing so, bought a case table derived
from RFC 9309 by a session that had not read `src/`. Running that table against
`integral.robots` as well as against the new reader costs nothing, and the
49 rows it opened with produced exactly one disagreement. Fixing the primary
matcher was not T120's job, so what T120 shipped is the proof plus a pin:

* `second_reader.REPO_MATCHER_DISAGREEMENTS` names each case, so a **new**
  disagreement appearing fails a test by name rather than moving a count;
* `status/evidence/T120.json` commits `repo_matcher_verdicts_against_the_rfc`.

**The pin then fired on T120's own pull request, and that is why this task is
scoped to the rule rather than to the row.** The independent read of that PR
found the same shortcut in the *new* reader — `_QUERY_DATA_OCTETS = ":/"`, the
two octets the example table happens to print — and derived cases 50 and 51 from
§2.2.2's text against it. Fixing the second reader generally (the reserved set
minus the two octets §2.2.3 gives pattern meaning to) closed both, and running
the now-51-row table against `integral.robots` moved the count from one to
three. So the primary matcher's defect was never "`:` and `/`"; that was the one
row of the table that reached it.

The pre-PR review's objection to stopping there is this task's reason to exist:
a pin with no expiry is a permanent green test asserting that a known fail-open
is still present, and this repository's rule is that an accepted finding is
committed *and owned*, not read and waved through.

## Scope

* **Reserved octets used as data in a query**, not `:` and `/`. Canonicalise
  every octet in RFC 3986's reserved range that appears as data in a query
  before comparison. A fix that adds `:` and `/` to some encode-here list and
  stops has fixed the three rows the table happens to carry and left the other
  eight reserved octets exactly as fail-open as they were — which is the defect
  this task was re-scoped away from, and the defect T120's own reader shipped
  with until its review.
* Say in the code what is **held out** and why, because that is the part a list
  cannot express. `*` and `$` carry §2.2.3 pattern meaning, and the query's
  opening `?` is what makes "in the query" decidable at all; those exemptions
  are reasoned, and every other one is a hole.
* `integral.second_reader.canonical` already implements one reading of this
  (`_QUERY_DATA_OCTETS`, plus the spellings that resolve a rule reaching the
  query through a wildcard). **Do not copy it.** The two matchers are worth
  having because they were derived independently; a `robots.py` written from
  `second_reader.py` is one matcher with two names, which is the exact failure
  T120 exists to have removed. Derive it from §2.2.2 and RFC 3986's `reserved`
  production instead.
* When it lands, `repo_matcher_verdicts_against_the_rfc` reads 0 and
  `REPO_MATCHER_DISAGREEMENTS` empties — the test that pins the set asserts both
  directions, so an empty pin over a non-empty finding fails too.
* T70's `robots_verdicts_misread` must stay 0: this changes canonicalisation, and
  that is the gate which exists because percent-encoding equivalence took ten
  defects across five review rounds.
