## Acceptance gate

```gate
repo_matcher_verdicts_against_the_rfc == 0
evidence: status/evidence/T120.json
key: repo_matcher_verdicts_against_the_rfc
status-key: gate_status
```

The metric already exists and already reads **1**. T120 wrote it, and this task
is what makes it fall — the gate is not a new measurement, it is the one T120
committed with nobody assigned to it.

## The defect

`integral.robots` — the matcher `CLAUDE.md` tells every session to adjudicate a
real board with — answers **ALLOW** for a path RFC 9309 refuses:

```
User-agent: *
Disallow: /foo/bar?baz=https%3A%2F%2Ffoo.bar
```

against the request `/foo/bar?baz=https://foo.bar`.

§2.2.2's own example table (row two, RECOLLECTED) gives that request the
"path to match" `/foo/bar?baz=https%3A%2F%2Ffoo.bar`: `:` and `/` appearing as
**data** inside a query value are reserved octets and are percent-encoded before
comparison, while the query's own delimiters (`?`, `=`) stay literal. So the rule
and the request are the same string and the rule refuses.

The cause is one constant. `robots.py`'s `_CHUNK_SAFE = "/:@!&'()+,;=?~-._"`
leaves `:` and `/` unencoded everywhere, including inside a query value, so the
rule and the request never compare equal and no rule matches.

**It is fail-open**, in the matcher that decides real fetches.

## How it was found, and why the finding is committed rather than fixed

T120 replaced the *second* reader and, in doing so, bought a 49-case table
derived from RFC 9309 by a session that had not read `src/`. Running that table
against `integral.robots` as well as against the new reader costs nothing and
produced exactly one disagreement — this one. Fixing the primary matcher was not
T120's job, so what T120 shipped is the proof plus a pin:

* `second_reader.REPO_MATCHER_DISAGREEMENTS` names the case, so a **second**
  disagreement appearing fails a test by name rather than moving a count from
  one to two;
* `status/evidence/T120.json` commits `repo_matcher_verdicts_against_the_rfc: 1`.

The pre-PR review's objection to stopping there is this task's reason to exist:
a pin with no expiry is a permanent green test asserting that a known fail-open
is still present, and this repository's rule is that an accepted finding is
committed *and owned*, not read and waved through.

## Scope

* Canonicalise reserved octets used as **data** in a query before comparison,
  while leaving the query's structural delimiters alone — the distinction
  §2.2.2's example table draws in its first two rows.
* `integral.second_reader.canonical` already implements one reading of this
  (`_QUERY_DATA_OCTETS`, plus the spellings that resolve a rule reaching the
  query through a wildcard). **Do not copy it.** The two matchers are worth
  having because they were derived independently; a `robots.py` written from
  `second_reader.py` is one matcher with two names, which is the exact failure
  T120 exists to have removed.
* When it lands, `repo_matcher_verdicts_against_the_rfc` reads 0 and
  `REPO_MATCHER_DISAGREEMENTS` empties — the test that pins the set asserts both
  directions, so an empty pin over a non-empty finding fails too.
* T70's `robots_verdicts_misread` must stay 0: this changes canonicalisation, and
  that is the gate which exists because percent-encoding equivalence took ten
  defects across five review rounds.
