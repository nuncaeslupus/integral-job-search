## What this is

The name was settled on 2026-08-18 (`docs/product-shape.md`, question 5):
**`integral-job-search`**. The rename is mechanical — nothing in the design was
ever named after the project — but it is wide, so it is its own change and
lands before the packaging work builds on the old name.

What moves:

- `src/jobsearch/` → `src/integral/`, and every import with it;
- the distribution name and console entry points in `pyproject.toml`;
- the repository name, and the URLs in documents that spell it out;
- `README.md`, and the install snippet in `docs/distribution.md` §1.

What does **not** move, and must not be renamed as collateral:

- `$INTEGRAL_HOME` — already written under the settled name (T51);
- `claude-arsenal/` and the queue ledger — the vendored bundle keeps its own
  name, and task ids are opaque;
- the thirteen step skill directories (`step-00-identify` …) — they are named
  after the process, not the project.

## The gate, and why it is a reference count

`old_name_references == 0` counts surviving references to the old name outside
an allowlist (this payload, the queue's historical rows, git history). A rename
that leaves a stale import fails at run time, and a rename that leaves a stale
*document* is worse — it sends the next reader to a repository that no longer
exists. Counting is the only way to know the sweep finished.

## Tests

`test_no_module_imports_the_old_package_name` in `tests/test_naming.py`;
`test_no_document_names_the_old_repository`;
`test_the_console_entry_point_matches_the_distribution_name`;
`test_the_preserved_names_are_not_swept` — `$INTEGRAL_HOME`, the arsenal bundle
and the step skills survive the rename unchanged.
