Imported from issue #550

Second half of #547, and it is the half that reached a candidate.

#547 fixed an over-rejection: a location regex threw away offers whose location field was empty. The replacement rule was *the board declares its market* — a Spanish board lists Spanish vacancies, and the location field only refines it. That rule accepts **every** offer from a Spanish board, which is not what reach means.

## Measured, one candidate, 2026-09-22

Constraints on file: `relocation.willingness: "no"`, `commutable_regions: ["Barcelona"]`, `authorised_countries: ["ES"]`.

| | of 124 "reachable" |
|---|---|
| remote stated | 35 |
| on-site / hybrid / not stated | **89** |
| mention Madrid | **45** |

A candidate who cannot relocate and commutes in Barcelona was handed 45 Madrid vacancies and 89 that require being somewhere. The candidate's own words: *"muchas no son remote y son de Madrid"*.

## The rule that is missing

Reach is `remote OR inside a commutable region`, per candidate — never `the board is in the right country`. Country is a work-authorisation test and a necessary condition; it was used as a sufficient one.

`unplaced` (#547) stays as it is: an offer whose location cannot be read is withheld and counted, never accepted and never rejected.

## Acceptance gate

```bash
uv run python -m integral.reach
```

`offers_presented_outside_every_commutable_region_and_not_remote == 0`, over a fixture set carrying all four shapes — remote stated, commutable city, non-commutable city in an authorised country, and no location at all. The third row is the one today's rule gets wrong and the one a gate derived from the current behaviour would bless.
