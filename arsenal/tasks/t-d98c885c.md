Batched non-blocking findings from the PR #914 second-reader round on t-07b591f4
(the profile_kit module). Neither is a trust-boundary or correctness-in-the-common-case
bug, so they were filed rather than fixed in that PR.

1. **Multi-line description bleeds out of the markdown bullet.** `_texts_md` renders
   each field as `- **{label}:** {value}`. A `description` with embedded newlines (a
   multi-paragraph job description from the store) puts lines 2+ outside the bullet, so
   they no longer read as part of that field when the texts.md is pasted into a profile
   site. Indent continuation lines, or render the value as a block.

2. **Source-suffix lookup is case-sensitive.** `_place_logo` matches `<slug><ext>` for
   ext in `_RASTER` (all lowercase). A file dropped as `<slug>.PNG` / `<slug>.JPG` is
   reported `missing` though a logo is present. Match the suffix case-insensitively.

Gate: add fixtures to tests/test_profile_kit.py pinning both — a multi-line description
whose continuation lines stay within the field, and an uppercase-suffix source that is
squared rather than reported missing.
