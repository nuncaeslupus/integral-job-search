## Why this carries `requires: [surface:human]`

The spec gates this task on the exhaustion signal *having been observed to be
right*, not merely built. `deps: [T68]` cannot express that — a dep resolves when
T68 **merges**, which is the moment the signal starts existing, not the moment
anyone has watched it fire on a real cycle.

So the prerequisite is enforced where the board can see it: `surface:human` is a
capability no worker surface declares, so `task_select.py` never offers this task
and only the candidate can start it. That is the same mechanism T20 uses, and it
is deliberate rather than a scheduling convenience — Option 3's failure mode is
asymmetric. A missed chance to ask costs one cycle; an unwanted interrogation
costs the candidate's willingness to keep using the tool.

**Do not remove `requires` to unblock the queue.** If the signal has been watched
and is trusted, a person says so and takes the task.
