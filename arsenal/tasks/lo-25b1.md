## Acceptance gate

```gate
prefilter_suppressed_positives == 0
evidence: status/evidence/T15.json
key: prefilter_suppressed_positives
```

```bash
uv run --extra dev pytest tests/test_extract.py tests/test_prefilter.py -q
uv run --extra dev python -m integral.extraction
```

The two blocks do different jobs and both are required. The `bash` block
regenerates `status/evidence/T15.json`; the `gate` block asserts the
number in it against the threshold. Without the first, a stale or hand-written
evidence file passes unchallenged; without the second, a command that exits 0
counts as a gate whatever it measured.

The `bash` block **regenerates** the evidence and exits 0 even when it has
suppressions to report; the `gate` block above is what asserts the threshold, and
`verify_gates.py` is what refuses to let this task be terminal while the assertion
fails. That division is deliberate and was moved here on 2026-08-25 — see the
reopening note below. A command that both measures and judges blocks every
`make evidence` in the repository behind a number whose right value is still a
decision, and a task whose measurement is undefined has still not passed its gate.

## Scope change — v2 plan, 2026-08-18

Two changes from specification v2, step 8.

**Staged, with the model last.** Extraction runs in stages, each cheaper than
the next: normalise the advert into the same fields every offer carries; take
what patterns and keyword rules can take outright — salary figures, contract
type, hours, location, named technologies; and send to a model only the
dimensions those could not settle, for the offers where it matters. Reading
every advert with a model is what makes this expensive enough to stop using, and
most of what an advert states is stated plainly.

**Extraction stays candidate-independent.** `extractions/<offer_id>.json` could
be cached or shared across profiles without leaking anything. Relating an offer
to *this* candidate moves to the local annotation pass, **T42** — the model sees
the advert and nothing else.

## Scope change — the gate's denominator, 2026-08-19

The hand-labelled corpus T5 was to supply is not coming (`lo-d2b2`). Three
requirements follow, all owned here; the reasoning is in D-2 (`lo-77a6`).

1. **Score only what a person decided.** `extraction_macro_f1` is computed over
   `Label` rows whose `source` is `human`, `confirmed` or `edited`. Never over
   `corpus/labelled/suggestions.json`, and never over `extraction.gold`.
2. **Refuse to emit the number below the label floor.** Too few human labels for
   a dimension means that dimension is *unmeasured* — the evidence file records
   it as such and names it, rather than carrying a figure computed from three
   rows. An unmeasurable gate must not resolve to a pass or to a fail.
3. **Emit `n` beside every score**, per dimension and in aggregate, so a reader
   of `status/evidence/T15.json` can see what the number rests on without
   opening the corpus.

Agreement against the pre-marks stays available as a separate, unthresholded
consistency figure under its own name. It is not F1 and must not be written to
the `extraction_macro_f1` key.

## Scope change — T14 folded in here, 2026-08-20

**T14 (`lo-3100`, #46) is absorbed into this task and cancelled.** Its lexical
prefilter is the middle stage the v2 note above already describes: "take what
patterns and keyword rules can take outright ... and send to a model only the
dimensions those could not settle". It was never a separate pipeline, only a
separate task file.

The reason for folding rather than sequencing is its gate. T14 declared
`prefilter_recall >= 0.98`, measured against the corpus positives T5 was to
supply — and T5 closed without the hand-labelling campaign (`lo-d2b2`).
`status/evidence/T5.json` records what actually exists:

    label_count               39, over 4 ads
    labels_by_split           elicitation 25 · evaluation 14
    labels_by_dimension       no dimension above 4; most at 1–3
    dimensions_without_labels mission_alignment, process_formality,
                              social_intensity, work_intensity

A recall figure over 14 evaluation labels is noise wearing a threshold. Kept as
its own task, T14 needed its own gate against a corpus that cannot support one,
and it blocked this task — and through it fifteen of the twenty-six live tasks —
on a measurement nobody could honestly take. Folded in, the prefilter is a stage
measured by *this* task's gate, which D-2 has already taught to report `n`, to
refuse a number below the label floor, and to name the dimensions it could not
score.

So the three requirements in the section above extend to the prefilter:

4. **The rules stage is measured as part of this gate, not beside it.** If its
   recall is worth reporting, it is reported under its own key with its own `n`,
   in `status/evidence/T15.json`. It is not thresholded separately, and
   `prefilter_recall` is not resurrected as a gate key while the label floor is
   unmet.
5. **Recall-orientation survives the fold.** The stage's job is unchanged: it
   may not drop an advert the corpus labels positive for any dimension. T14's
   named test comes with it —
   `test_prefilter_retains_all_corpus_positives` in `tests/test_prefilter.py` —
   and is written RED like the others. What changes is that failing it is a
   failure of this task, not of a gate that could not be measured.

T14's payload is at `arsenal/tasks/_history/lo-3100.md` with `status: cancelled`,
which is deliberately **not** terminal: it records that the work was absorbed
rather than done, so nothing reads it as a completed prefilter.

## Implementation landed, gate not met — 2026-08-20

`src/integral/extraction.py` implements all three stages, with
`tests/test_extract.py` and `tests/test_prefilter.py`. The step-08 skill can
use it today: `extract(offer, dimensions)` runs stages 1–2, `model_request`
says exactly what is still unsettled, and `accept_model_scores` validates what
comes back — refusing a span that is not in the advert, a dimension nobody
asked about, and the same dimension twice.

**Two design decisions came out of measurement rather than argument**, both
found by the folded prefilter check catching real suppressions in the committed
corpus:

1. **A bipolar dimension is not settled by one keyword.** "Ejecutar las tareas
   asignadas con autonomía" contains *autonomía* and means close to its
   opposite; a person labelled it −0.6 while a single +0.7 cue settled it +1.
   On a bipolar scale one keyword is evidence of the *topic*, not of a
   direction, so the dimension stays on the model's agenda. Unipolar dimensions
   are exempt: there a single match really is presence.
2. **Unipolar scales have no negative class.** A person wrote "Sin viajes ni
   guardias" as `value=0.0, negated=True`, which `harness._sign` reads as −1,
   while the cue matching the same phrase carries `0.0`. Two encodings of one
   agreement were being counted as a disagreement.

`prefilter_suppressed_positives` is **0 over 36 positives checked**, and
`test_the_suppression_check_would_notice_a_bad_cue` inverts a committed cue to
show the check still has teeth.

**The gate is not met, and cannot currently be met.** `extraction_macro_f1` is
`null` / `unmeasured` — the only honest value under D-2 with 14 evaluation
labels against a floor of 10 — and `gate_evidence` reads a null as a hard
failure because it has no third outcome. That is **D-12 (`t-e1ca8374`, #83)**,
held for an owner decision, with the upstream half filed as claude-arsenal#168.
Until D-12 is resolved this task stays open however finished the code is: its
acceptance is a measurement, and the measurement has not been taken.

## Scope change — the acceptance splits, 2026-08-22

**D-12 (`t-e1ca8374`, #83) resolved by splitting this task's acceptance.** The
section above describes one task holding two claims: *the extractor is not
broken* and *the extractor scores well enough*. Only the first is measurable
today, and binding them together held fifteen live tasks behind a number nobody
could honestly take.

**This task's gate is now `prefilter_suppressed_positives == 0`** — already
computed, already `0` over 36 positives checked, and already the thing that
found both design decisions above. It is the property of the extractor this
task actually built.

**`extraction_macro_f1 >= 0.75` moves to T56 (`lo-6f53`)**, blocked on T25
(`lo-1af2`) and T26 (`lo-9e41`) — the corpus work that has to land before there
are enough human labels to score against. A scoring gate whose prerequisite is
labels belongs behind the labels.

Nothing here is relaxed. The floor stays at 10 per dimension, the denominator
stays human-decided labels, and the number is still refused below the floor —
the requirements above are unchanged and are carried into T56 verbatim. What
changes is *which task* is held open by them.


## Reopened — 2026-08-25, the gate stopped holding against a real corpus

`prefilter_suppressed_positives == 0` is **2 / 209** after T56's round 2, so this
task can no longer show the measurement its terminal status claimed and
`verify_gates.py` says so. Reopened rather than left archived with a failing gate:
an archived task whose gate does not hold is the one state this board may not be in.

**Neither suppression is a cue bug, and neither is fixable without cheating.**
Both are adverts carrying evidence at *both* poles of a bipolar dimension, where
the cue set has vocabulary for only one:

| advert / dimension | the advert | person | cues |
|---|---|---|---|
| `manfred-8360` / `process_formality` | "se huye de los *sprints* infinitos… Funcionan con **Kanban**" | -0.6, rejects ceremony | +0.5, matched `sprint` and `Kanban` |
| `tecnoempleo-5daa18bff2393309c941` / `stack_modernity` | Kubernetes and cloud, **and** "Experiencia sólida en JBoss / JBoss EAP" | -0.7, weighed the legacy | +0.53, saw only the modern |

One structural cause was found and fixed in the same diff: `process_formality` is
bipolar with a declared `-0.6` rung and carried **zero negative-pole cues in any
language**. That is provable from the cue set alone and needed no label to find.
Cues written from the rung's own `tell` were added — and they do **not** resolve
`manfred-8360`, because that advert says "se huye de los sprints infinitos", which
is a rejection phrased with a verb the negator list does not carry. Reporting that
honestly is the point; extending `_NEGATORS` to match one advert would be fitting
to the evaluation split.

`stack_modernity`'s case is not reachable at all without adding legacy-stack
vocabulary chosen by looking at an evaluation-split miss, which is D-2's failure in
a new costume.

**What this task now needs is a decision, not a patch.** `== 0` was set when the
corpus held four labelled adverts and measured nothing; at thirty-three adverts and
209 positives checked it is a rate with no denominator in the gate. Either the
threshold acquires one, or the two cases are accepted and named. Do not resolve it
by tuning cues until the number reads zero.
