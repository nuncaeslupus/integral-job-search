## What happens

T74 (#213) made `read_response` check that the page it fetched is *the advert*,
not merely that the URL resolved. That is the right check and it fails in the
safe direction — `unverified` withholds rather than tombstones. But on a live
run it withheld **64 of 178** adverts (36%), and at least two of the three
causes are the check being too literal rather than the page being wrong.

Measured 2026-09-22, every URL fetched by hand and confirmed HTTP 200 with the
advert on screen.

### 1. A composed title never appears verbatim on the page (weworkremotely, 8/8)

```
stored title : 'A.Team: Senior Independent AI Engineer / Architect'
page <h1>    : 'Senior Independent AI Engineer / Architect'
page <title> : 'Remote Senior Independent AI Engineer / Architect at A.Team'
verdict      : unverified — "the page does not mention '…'"
```

The connector composes `"<company>: <role>"` into `title`. The page states the
same two facts in the other order, so the literal substring is absent from a
page that names both halves. The advert is live and is withheld.

### 2. A canonical redirect reads as a different page (ticjob)

```
requested : https://ticjob.es/esp/busqueda/trabajo/full-stack-developer-java-ai-native-ingles-alto/70691
landed on : https://ticjob.es/esp/trabajo/full-stack-developer-java-ai-native-ingles-alto/70691
verdict   : unverified — "that is some other page, not this vacancy"
```

Same host, same slug, same numeric advert id — the site drops a `/busqueda`
path segment. `same_page` compares the whole path, so a site that canonicalises
its own URLs is read as having redirected the advert away. Note the title check
**passed** on this one (the title is in the body); the URL comparison overrode
it.

### 3. A JavaScript-rendered page carries no advert text (foorilla, 50/50)

```
page <title> : 'all Hiring'
page <h1>    : none
bytes        : 11810
```

Here `unverified` is the **correct** verdict — the advert really is not in the
HTML. But the consequence is that a board contributing 50 offers in one run
contributes zero presentable ones, every run, silently. `connector.yaml` should
declare `client: browser` for it as InfoJobs does, so `source()` reports the
board skipped and the candidate is told, instead of the offers being collected
and then quietly withheld one advert at a time.

## The change

Two fixes and one declaration:

- **Identity by the facts the page states, not by one string.** An advert is
  confirmed when the page names the role; the company is corroboration, not a
  required prefix. Compare the stored title against the page's `<h1>`/`<title>`
  with a normalisation that is stated as a rule — casefold, collapse
  whitespace/punctuation, and require the *role* tokens — rather than a list of
  separators (`:`, `-`, `at`, `@`) to strip. An enumeration of separators has no
  last element; the next connector composes it differently.
- **Two URLs naming the same advert are the same page.** Where a site exposes a
  stable advert id, matching it is the closed rule; a path-prefix difference on
  the same host with the same id is a canonicalisation, not a redirect away.
- **Declare `client: browser` on foorilla** so the skip is reported up front.

## Why it matters

The candidate is told "N found"; they are shown N − 64. The skill requires the
withheld count be reported, and it was — but a withheld count that is mostly
this check misfiring trains everyone to ignore it, which is how the count stops
doing its job.
