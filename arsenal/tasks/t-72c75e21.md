Imported from issue #559

Found while fixing #558. Unblocking every board (#558) was the **first** of two blockers, not the only one. After that fix, only **19 of 1,246** readable offers in one candidate's store pass `check_stimulus`.

## Measured

One candidate's store, 2026-09-23:

```
offers in store                 1314
fetched_at is null              1281
```

`reaction_elicit.check_stimulus` refuses any live stimulus whose `fetched_at` is unset — deliberately, because a stimulus with no provenance is indistinguishable from one the model wrote. That refusal is right. What is wrong is that nothing on the sourcing path ever sets the field.

## Why the field is empty

`connectors.build_offer` (`src/integral/connectors.py:3838`) has **no `fetched_at` parameter at all**, so no connector can supply it even if it wanted to.

And that is deliberate. `src/integral/lifecycle.py:178-183` says so:

> T11's `connect_manual` leaves `fetched_at` `None` unless a caller supplies it (§5.2: 'a connector may not invent fields') … So this module keeps its own clock rather than depending on an optional field a connector is free to leave unset.

So the provenance clock the spec actually keeps is `LifecycleRecord.collected_at`, while `check_stimulus` demands `Offer.fetched_at`. **Two clocks, and the check reads the one nothing writes.**

## What this is, and what it is not

This is a **spec question**, not a typo, and it should not be decided inside #558:

- §5.2 forbids a connector inventing fields. Is the moment *we* fetched a page a field the connector invented, or a fact about our own request?
- If it is ours, `build_offer` can stamp it and the whole store backfills from `_fetches.jsonl`.
- If it is not, `check_stimulus` should read `collected_at` off the lifecycle record instead, and `Offer.fetched_at` stops being the provenance the reaction step relies on.

Either answer unblocks reactions on the existing store. Picking one without settling §5.2 puts a second clock in the codebase.

## Acceptance gate

```
offers_a_candidate_can_react_to_with_no_provenance_clock == 0
```

Pinned in both directions: an offer with a real fetch behind it must be reactable, **and** an offer with none must still be refused. A gate that only counts the first is satisfied by deleting the check.
