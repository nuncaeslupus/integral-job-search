## Why this exists

Two readers decide whether a task file declares a gate, by different rules:

- **`claude-arsenal/scripts/gate_evidence.py:74`** finds the section with
  `##\s+Acceptance gate` and takes the **first** match, then searches only inside
  it for a fenced ` ```gate ` block. `src/integral/task_gate.py:108-109` and
  `claude-arsenal/bin/gate_run.sh:206-212` use the identical grammar.
- **`tools/verify_gates.py:115`** decides "declares a gate" from the substring
  ` ```gate ` **anywhere in the payload**.

When they disagree the task is counted among "gate(s) asserted" and then checked
by a reader that asserts nothing — and the count of asserted gates goes **up**,
so nothing looks wrong.

**Measured on #334.** `t-2a30f58a.md` (T118) and `t-246f6dde.md` (D-29) wrote
their label as `**Acceptance gate**` — bold text, not a heading. Simulated at
terminal with no evidence files present:

```text
verify-gates: 3 terminal task(s); 3 gate(s) asserted, 0 carry no fenced gate block
  FAIL t-05717b64: evidence file not found: status/evidence/T109.json
```

T109 fails correctly. T118 and D-29 pass, with their evidence files never read
and not required to exist. Both were repaired in #334; **the gap that let them
through is untouched**, and the next task file writing the label in bold falls
into it.

`gate_run.sh` is equally blind: with no fence in the first `##` section it skips
the evidence gate and falls through to the placeholder `false`, so the
`ARSENAL_GATE_FROM_DEFAULT=1` bootstrap hands the gate command back to the
implementer's own branch with no evidence assertion behind it.

## Scope

- One reader, or two that provably agree. The cheapest honest fix is for
  `verify_gates.py` to ask `task_gate` whether a gate is *readable*, rather than
  grepping for a substring — but any arrangement where "counted as asserted" and
  "actually checked" cannot diverge is acceptable.
- **The metric counts the divergence, not the fences**: for every terminal task,
  the number counted as asserting a gate that the evidence reader does not
  actually read. It is the disagreement that is the defect.
- A fixture per way a fence can be present and unread: bold label, label in a
  later section, a fence outside any Acceptance-gate section, a second fence
  after the first, no `##` section at all.

## Denominator

`gates_compared_at_least` — a **floor** (T100's precedent), never the count of
the day, which moves on every task PR. Zero divergences over a scan that found
no task files is the vacuous pass this repository keeps finding.

Note the metric is named after a **wrong outcome**, not a category, per T123.
