Imported from issue #310

Found while capturing the four probes for #260. Not about those connectors — it is about the adjudication rule every connector in this repository is admitted under.

## The rule

`connectors/ruled-out.yaml` requires that the repo's own matcher **and** a second, independent parser agree before a path is fetched, plus a negative control so that a `True` is distinguishable from a matcher that says yes to everything. The second parser is stdlib `urllib.robotparser`.

## The defect

**CPython's `robotparser` returns the *first* matching rule in file order, not RFC 9309 §2.2.2's longest match.** `Entry.allowance` iterates the rule list and returns on the first `applies_to` hit.

So on any robots.txt that opens with `Allow: /`, it answers `True` for **every** path in the file — including every path a later, longer `Disallow` covers. Measured on two live boards:

| host | target | repo matcher | stdlib | control | repo | stdlib |
|---|---|---|---|---|---|---|
| himalayas.app | `/jobs/api?limit=20` | True | True | `/apply`, `/jobs?page=2` | **False** | **True** |
| nofluffjobs.com | `/Python?page=1` | True | True | `/api/posting/123`, `/posting/abc` | **False** | **True** |

Both files open with `Allow: /`. `robotparser` never returned False on either one.

## Why it matters

The error is **fail-open**, and it is fail-open in the exact component that exists as the independent check. Two matchers agreeing means something only when both can disagree; here the second one cannot say no at all, so the rule silently becomes "the repo matcher decided" while the file records a two-parser adjudication. Every board admitted over a permissively-opening robots.txt was adjudicated that way.

Nothing was fetched that should not have been — the repo matcher is strictly stricter and it carried the verdicts. The hole is in the evidence, not (yet) in the behaviour.

## Related, and part of the same gap

`www.workingnomads.com`'s entire robots.txt is `User-agent: *` / bare `Disallow:`. No path on that host is disallowed, so **no negative control can exist**. The rule has no answer for that case today, and the honest thing — saying so — is currently indistinguishable from forgetting to do it.

## Scope

- Make the second parser's **competence** part of the adjudication, not assumed: before trusting an agreement, show the second parser returning False for at least one path on that same file. Where it cannot, the adjudication is single-parser and must be recorded as such rather than counted as agreement.
- Or replace the stdlib as the second reader with one that implements longest-match, and keep the competence check anyway — this failure was invisible precisely because nobody asked the second reader to prove it could refuse.
- Give "no negative control is possible on this file" its own recorded verdict, distinct from "no control was run".

## Gate

`robots_adjudications_without_a_competent_second_reader == 0`, denominated by every adjudication in `ruled-out.yaml` and every shipped connector package, with a floor so a scan that finds none reports `unmeasured`.
