An annotatable HTML reader for any document this tool generates, so the candidate
edits by fragment instead of by retyping a paragraph into chat.

Built by hand for a live application on 2026-09-07 (`make_reader.py`, in that
candidate's `cv/generated/<offer>/v5/`); this task is to make it part of the tool.

**What it must do**

- One fragment per `<p>`, `<li>`, `<h2>` and per header line; a note box beside each,
  on the right at any width a document is actually read at.
- Notes autosave in the browser, keyed by fragment id.
- **Export** to Markdown: fragment id, a quote of the source, the note.
- **Import** that same file back, so a returned export re-seeds the reader.
- **Every string the reader shows is translated.** The candidate reads in Spanish,
  Catalan or English while the document itself is in the employer's language — the
  two are independent, and the reader carries the candidate's.

**The measurement, and why it is behavioural.** `reader_fragment_defects` counts
contract failures over a generated reader, not pattern matches in its source. Two
defects were met by hand and each has a contract:

1. A `<div>` accepted as a fragment boundary swallowed a whole `<div class="letter">`
   — eleven paragraphs became one note box, and the CV shipped eight unclosed `<div>`s.
   Contract: every fragment balances its own tags, and no fragment contains another.
2. A single 25-character floor dropped short headings, so `Projects` had no note box
   and `Education & certifications` did — inconsistently, in the same document. The
   `opos` project header (18 characters) was missing too. Contract: every heading and
   every header line in the input appears as its own fragment, whatever its length.

3. The export button was inert for a whole round because a double-unescaped `\n`
   put a literal newline inside a JavaScript string. That is a syntax error, so the
   browser discarded the entire `<script>` — nothing autosaved either, and the only
   thing still working was typing into a box, which is HTML. Contract: the generator
   parses the script it emits (`node --check`) and refuses to write a reader whose
   JavaScript does not compile.
4. A note box that sat *below* a short fragment instead of beside it. Contract: the
   box is to the right of its fragment at every width the reader is used at.

Every one of these looked almost right, which is why reading the generator cannot be
the check. Defect 3 is the case in point: the file it produced was well-formed HTML
and the bug was one character inside a string.
