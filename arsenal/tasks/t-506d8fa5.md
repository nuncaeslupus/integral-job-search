> Regarding evaluation of hundreds of ads, don't you have some automatic
> tooling? If not, you should. So retrieving a lot of jobs with connectors
> (scrapers) and filtering them automatically should be offered by the tool.

The connector library can now return volume — thirteen packages, and the
JSON-reading ones return whole result sets in one request. The pipeline behind
them was built for the handful of adverts a manual round produced, so volume
arrives and is triaged by reading.

This is what makes T91 safe to build: a loop that keeps adding connectors is
only an improvement if what they return can be reduced without a person in the
loop. Otherwise more coverage is more work.

Bounded deliberately: **filter, not rank**. Ranking is step 9 and has an owner.
This is the cheap pass before it — hard constraints, eligibility, expiry,
duplicates, and stated exclusions (T90) — reducing a few hundred rows to the
tens that are worth understanding.

## Acceptance gate

```bash
uv run --extra dev pytest tests/test_bulk_filter.py -q
uv run --extra dev python -m integral.sourcing_cycles --bulk
```

- `test_a_few_hundred_offers_reduce_without_a_human_decision`
- `test_every_rejection_records_which_rule_dropped_it` — a filter that cannot say
  why is a filter nobody can trust or debug.
- `test_the_filter_never_drops_on_a_soft_preference` — soft goes to ranking, and
  only hard rules delete.
