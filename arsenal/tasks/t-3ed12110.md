**Where:** `src/integral/offers.py:293-305, src/integral/offers.py:396, src/integral/lifecycle.py:279-280, README.md`

### Finding
Offer ids are `sha256:<digest>` and are used verbatim as file names for the offer body and its lifecycle record. README says the profile lives in the platform user-data directory 'on macOS and Windows', but on NTFS a colon is a stream separator: every offer is written into an alternate data stream of one file named `sha256`, and `glob('*.json')` then finds no offers.

### Evidence
Traced id -> filename with no sanitising (`grep 'replace(":"' src` empty). Not executed on Windows; CI runs ubuntu-latest only (ci.yml:70,85,99,117).

### Suggested direction
Map ids to a filesystem-safe name (e.g. `sha256-<hex>`), with a read-side fallback for existing stores, or drop the Windows claim; add a windows-latest CI job if the claim stays.
