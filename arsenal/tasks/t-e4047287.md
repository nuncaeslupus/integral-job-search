Found while fixing a CodeRabbit finding on #289 (T99). Out of scope there — different module, different gate — so recording it rather than widening that PR.

`src/integral/connector_policy._as_date` accepted two non-canonical `decided_on` values:

- a **`datetime`**, because `isinstance(datetime(...), date)` is `True` — a YAML timestamp passes a check written for a plain date;
- an **unpadded string** like `2026-8-1`, because `datetime.strptime(..., "%Y-%m-%d")` accepts it.

Both are now rejected there, with fixtures in `MALFORMED_CONTROLS`.

`src/integral/connector_contract.py` has its own `_as_date` with the same shape, and `isinstance(raw, date)` checks at roughly `:299` and `:325`. The same two values would pass.

## Why it is worth doing

Connector packages carry a capture date, and T72 built the rot stage on it — a date that is silently a `datetime`, or that is not the day the file claims, is a wrong answer from the thing deciding whether a fixture has gone stale. It is not urgent; nothing is known to be feeding either shape today.

## Scope

Small. Either lift the corrected `_as_date` into one shared helper both modules import, or apply the same two guards in place. Whichever is chosen, the accepted cases go into the relevant gate's fixtures and its denominator rises — the same rule that governed the T99 fix.
