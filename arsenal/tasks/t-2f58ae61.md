## Where this comes from

`claude-arsenal/scripts/create_reader.py` derives a reader's annotatable
sections from `##` headings. A cover letter is eleven paragraphs and **no
headings at all**, so the whole letter becomes one section — one comment box for
a document whose entire review consists of per-sentence corrections. On the
DOMMA letter that was worked around by writing a headed copy to a temp file,
which then had to be kept in sync with the real one by hand for five rounds.

`references/annotatable-reader.md` says a document handed to a person for
annotation needs a reader. Every candidate-facing document this repository
produces — letters, LinkedIn messages, profile summaries — is heading-less, so
that is the whole class, not one document.

## What to build

The fix is ours, not upstream's: the vendored bundle is refreshed by `/init` and
must not be hand-edited. So pre-process before calling `create_reader.py` —
when a document has fewer than two `##` headings, split it into one section per
paragraph and label each by its first few words.

## Tests

`test_headingless_document_gets_one_section_per_paragraph`.

`test_a_headed_document_is_passed_through_unchanged` — the existing behaviour is
