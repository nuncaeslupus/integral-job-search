**Where:** `src/integral/identity.py:530-572`

### Finding
The active candidate is one file `<root>/.active.json` holding a single {handle, session_id}. When session B identifies bob while session A (alice) is still open, A's `read_active_handle` no longer matches its session id and returns None, so the guard refuses every profile read/write in A with 'no candidate is identified yet'. The write is also a plain `write_text` (not atomic), so a concurrent read can see a truncated file and get the same refusal.

### Evidence
Traced: write_active_handle overwrites the single marker (565-571); read_active_handle returns None when payload['session_id'] != session_id (548); guard_decision denies with active=None (654-657). CLAUDE.md itself describes running 2-3 concurrent sessions.

### Suggested direction
Key the marker by session (`.active/<session_id>.json`) and write it via temp file + os.replace.
