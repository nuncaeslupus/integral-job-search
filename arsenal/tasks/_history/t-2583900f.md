> **Decided: resolution A.** The hold (`requires: [surface:human]`) is lifted
> because the decision it was protecting has been made by the owner —
> `parse.py` is withdrawn from the shape rather than given a sandbox. What
> remains below is the record of why, and the gate that keeps it true.

## Acceptance gate

```gate
advertised_connector_mechanisms_without_a_runtime == 0
evidence: status/evidence/D10.json
key: advertised_connector_mechanisms_without_a_runtime
```

```bash
uv run --extra dev pytest tests/test_connector_shape.py tests/test_connector_contract.py -q
uv run --extra dev python -m jobsearch.connector_shape
```

The two blocks do different jobs and both are required. The `bash` block
regenerates `status/evidence/D10.json`; the `gate` block asserts the number in
it against the threshold.

`connector_shape` exits **3**, never 0, when §5 cannot be read — no heading, no
fenced block, no filenames in it. A shape that could not be read has measured
nothing, and reporting 0 would make a deleted section look like a clean bill of
health. That is the inert-gate failure this task is an instance of, so the gate
for it must not be able to fail the same way.

## What the spec requires

`docs/distribution.md` §5 lists `parse.py` in the shape of every shared
connector:

```
connectors/<site-id>/
  connector.yaml     what to fetch, and the mapping to the offer schema
  parse.py           optional, only where the declarative form cannot express it
  ...
```

and describes it as the escape hatch "for sites that need it" — i.e. sites the
selector grammar cannot express. That is a promise a contributor can act on.

## What the code does

Nothing executes it. `connectors.py` interprets `connector.yaml` and matches
selectors; there is no import machinery anywhere in `src/jobsearch`, and T53's
`connector_contract` only ever reads `parse.py` as text to check it statically.
So a connector for a site the declarative form cannot express can be written,
can pass the whole conformance check, and cannot work.

Surfaced by review on PR #77, and seeded rather than resolved inside T53
because either resolution is a design decision, not a worker's call.

## The two resolutions, and what each costs

**A — remove `parse.py` from the shape until safe execution exists.** Honest
immediately: the shape then contains only what the tool can actually run. The
cost is that sites needing more than selectors have no path at all, so the
declarative grammar has to grow to meet them (JS-rendered pages already sit
outside it — see `connectors.py`, "What the format does not cover").

**B — define its interface and run it under real isolation.** Keeps the escape
hatch. The cost is that the AST allowlist T53 ships is *admission lint*, not a
sandbox, and must not be mistaken for one: a static allowlist cannot bound what
Python does at runtime. Executing contributed code needs process-level
isolation — separate interpreter, no network namespace, read-only filesystem,
CPU and memory caps — and a defined `parse(text) -> str` contract the
conformance check can then exercise against the fixture.

**Do not resolve this by relaxing the static check.** The check being
insufficient as a sandbox is an argument for isolation or for removal, never
for admitting more.

## What was decided, and why — resolution A

`parse.py` is withdrawn from the shape. `docs/distribution.md` §5 no longer
names it, `OPTIONAL_ENTRIES` is empty, and a package containing one is refused
by rule 1 with a message that says why rather than "unexpected file" — a
contributor who wrote one did what §5 told them to.

Three things decided it:

* **B is a milestone, not a parser.** Real isolation means a separate
  interpreter, no network namespace, a read-only filesystem, and CPU and memory
  caps, plus a `parse(text) -> str` contract for the conformance check to
  exercise. That is a lot of machinery to keep a hatch with no current user.
* **The hatch has no user.** The one committed connector has no `parse.py`, and
  `test_nothing_in_the_codebase_executes_a_contributed_parse_module` already
  asserted nothing runs one. A withdrew the promise to match a fact that was
  already true and already tested.
* **T54 was written assuming A.** The connector exchange (`lo-892b`, #70)
  installs third-party packages from a remote manifest, and its own disclosure
  list names connector, fixture and metadata — not `parse.py`. Shipping T54
  while the shape still advertised an unexecuted module would have distributed
  the defect rather than contained it, so this had to be settled first.

Rules 3 and 4 now hold **structurally**: rule 1 admits no Python module, and
data cannot open a socket. The AST allowlist is retained as a second line —
it fires on a module smuggled past rule 1 — but it is no longer what holds
those rules, which matters because it was never strong enough to be.

The measurement is `jobsearch.connector_shape`, which reads §5's fenced block
and subtracts the mechanisms this repository can execute (`EXECUTED_ENTRIES`,
declared and empty). Re-advertising `parse.py` in prose alone fails the gate in
the same commit. If resolution B is ever built, its commit adds `parse.py` to
`EXECUTED_ENTRIES` and the gate stays green honestly.
