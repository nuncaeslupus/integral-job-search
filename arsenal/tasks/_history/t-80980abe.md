Filed from a candidate session (test-mode 658fcce2).

Measured 2026-10-02 on one candidate's store, offers whose `company` is empty: tecnoempleo **101 / 349**, pythonorg **8 / 16**, foorilla 527 / 527 (T235). Nothing counts them at sourcing, and a card is built from them with a blank employer. An employer-keyed decision — a ruled-out employer (T228), the consultancy exclusion, 'ruled out before' matching on company and title — silently skips every one.

The closed rule, not three connector patches: an offer built with no employer is counted per board in the run's report, and a connector whose own fixture yields an empty `company` fails its gate unless `connector.yaml` declares the board does not publish one.


## Acceptance gate

```bash
uv run pytest tests/test_employer_published.py -q
```

## Done

- `BoardOutcome.no_employer` counts, per board, offers built and kept with no employer name; `Run.summary()` prints a `NO EMPLOYER` line saying whether the board declares the omission.
- `connector.yaml` gains `employer_unpublished: "<reason>"` (validated non-blank). A connector whose own fixture yields an empty `company` fails the gate unless it declares it, and a declaration with no empty row left fails too.
- Declared: tecnoempleo (aggregator postings genuinely anonymous), and two **gaps** where the board does publish an employer: pythonorg (bare text node the selector grammar cannot reach) and foorilla (T235 owns it).
- `offers.names_an_employer` is the one definition of "no employer" for employer-keyed decisions.
