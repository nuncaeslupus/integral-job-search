`ListPage.url_pattern` is a URL. There is nowhere in the schema to put a method
or a request body, and `collect_listing` issues a GET, so a board whose listing
is a POST is unreachable no matter how public it is.

**usajobs.gov is the concrete case, and it is already in `corrected`.** Its
front end searches with

    POST https://www.usajobs.gov/Search/ExecuteSearch
    Content-Type: application/json
    {"Keyword": "python", "ResultsPerPage": 25}

which answers 25 rows to a plain curl under this tool's own product token — no
key, no cookie, no session. robots.txt disallows only `/Content/`, `/Scripts/`,
`/foresee/` and `/Service References/`, so this path is allowed (re-checked
2026-08-31, after the capture, per test 3's second half in
`connectors/ruled-out.yaml`). The board sits in `corrected` describing a
surface nothing in this repo can fetch.

This is not one board's quirk. A POST whose body carries the whole query is the
ordinary shape of a modern search back end — idealist.org's Algolia call is the
same shape, and is ruled out for a second reason (it carries a key).

## What it probably needs

* a `method` on `ListPage`, defaulting to `GET` so every existing file is
  unchanged;
* a request body, declared as data. JSON is what the cases need. It must be
  literal — a body assembled by templating is a second injection surface, and
  `url_pattern` already refuses every brace but `{page}` for that reason;
* pagination in the body, because a POST board paginates in its payload rather
  than in its URL — which is where this meets the record-cursor limit
  `himalayas_en` and `remoteok` both record.

  "Literal body" and "substitute the page" are only compatible if the exception
  is written down, so here it is rather than left to the implementer:

  - **The substitution is on the parsed structure, never on the serialised
    text.** The connector declares JSON; the loader parses it once at load
    time; the fetcher walks the resulting object and replaces values. Nothing a
    connector writes is ever concatenated into a string that is then parsed as
    JSON, so there is no escaping question and no way to change the body's
    *shape* — which is the whole difference between this and string templating.
  - **One placeholder, `{page}`, and only as a complete value.** A JSON string
    whose entire content is `"{page}"` becomes the page number as a JSON
    NUMBER. `"page {page} of many"` is not a placeholder; it is a string
    containing braces, and it is passed through untouched — or refused, if the
    implementer prefers loud over literal. Say which, and test it.
  - **A brace anywhere else in the body is refused at load**, the same posture
    `url_pattern` takes. That is what stops the next contributor reintroducing
    general templating one convenience at a time.
  - **A key may not be a placeholder.** `{"{page}": 1}` is refused. Only values
    substitute; a body whose *shape* varies by page is not a literal body.

  The failure this contract prevents in each direction: too narrow and a real
  paginating board is rejected; too broad and `str.format` is back, over a
  connector-supplied string, with an attribute-traversal surface behind it.
* `Content-Type` follows from the body's declared form rather than being a
  third thing to get wrong.

## Watch for

`connector_health`'s baseline is `fixture/list.html` — one file, one response.
A POST connector's fixture is still one response, so nothing there changes; but
`compare_har.py` cannot currently tell two POSTs to the same URL apart
(nuncaeslupus/claude-arsenal#308), so a capture-based check on such a board is
weaker than it looks until that lands.


## Acceptance gate

```gate
boards_readable_only_by_post == 0
evidence: status/evidence/T89.json
key: boards_readable_only_by_post
status-key: gate_status
```

`build_list_requests` is the name this task gave the seam, and the
implementation kept it — so the block below runs exactly as written.

Three properties, because each can be green while the other two are broken. A
schema that accepts `method: POST` and no board using it proves nothing. A board
package that parses a fixture proves nothing about the transport — `parse_list_page`
never fetches, so a `method: POST` field that no request path honours passes it.
And a POST route that quietly changed what a GET connector sends would break every
existing package silently.

So the gate asserts the **request the engine would issue**, through a stub that
records it and sends nothing. `build_list_requests` is the name this task gives
that seam; an implementation choosing another name updates this block in the same
diff.

```bash
# Named, not matched by substring: `-k page_placeholder` already selects the
# existing `test_build_list_urls_fills_only_the_page_placeholder`, so a loose
# pattern reports a green half over a test this task did not write.
uv run pytest -q "tests/test_connectors.py::test_a_list_page_may_declare_a_post_method_and_a_literal_body" "tests/test_connectors.py::test_a_templated_request_body_is_refused_at_load" "tests/test_connectors.py::test_the_page_placeholder_substitutes_as_a_json_number" "tests/test_connectors.py::test_the_usajobs_package_parses_its_fixture_to_offers" \
  && uv run python -c "
from pathlib import Path
from integral.connector_contract import check_package
from integral.connectors import build_list_requests, load_connector, parse_list_page

package = Path('connectors/usajobs_en')
report = check_package(package)
assert not report.violations, report

connector = load_connector(package / 'connector.yaml')
requests = build_list_requests(connector)
assert requests, 'no request built'
first = requests[0]
assert first.method == 'POST', first.method
assert first.headers.get('Content-Type') == 'application/json', first.headers
assert isinstance(first.body, (bytes, str)) and first.body, 'POST with no body'

# {page} substitutes as a JSON NUMBER, on the parsed structure. Asserting only
# that the literal '{page}' is gone would pass a body that dropped the field, or
# set it to the wrong page, or set it to the string '1'. Name the field, the
# value and the type.
import json
paged = json.loads(first.body if isinstance(first.body, str) else first.body.decode())
page_field = connector.list.pagination.param
assert page_field in paged, (page_field, sorted(paged))
assert paged[page_field] == connector.list.pagination.start, paged[page_field]
assert type(paged[page_field]) is int, type(paged[page_field])
assert '{page}' not in json.dumps(paged), paged
second = requests[1] if len(requests) > 1 else None
if second is not None:
    later = json.loads(second.body if isinstance(second.body, str) else second.body.decode())
    assert later[page_field] == connector.list.pagination.start + 1, later[page_field]

# EVERY existing connector is still a GET with no body — the default did not
# move. Enumerated from disk rather than listed here, so a package added after
# this task was written is covered without anyone remembering to add it.
for path in sorted(Path('connectors').glob('*/connector.yaml')):
    if path.parent.name == package.name:
        continue
    plain = build_list_requests(load_connector(path))[0]
    assert plain.method == 'GET', (path.parent.name, plain.method)
    assert not plain.body, (path.parent.name, plain.body)

rows = parse_list_page(connector, (package / 'fixture' / 'list.html').read_text())
assert len(rows) >= 10, len(rows)
print(f'usajobs_en: POST request built, {len(rows)} rows parsed from its fixture')
"
```
