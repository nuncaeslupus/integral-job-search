Follow-up from #601's second reader (N3). T219 (`integral.stack_fit`) computes each
offer's stack fit and `rank(..., stack=...)` carries it under `stack_fit`, but the T44
card (`src/integral/presentation.py`, `card()` / `render()`, rows in `_CARD_ROWS`)
never shows it. So "this offer names Go, TypeScript and Kubernetes; your CV has none"
reaches the candidate only if the model follows the step-09 skill's prose — the
exact "a paragraph assembled by a model" the card exists to replace.

## What done looks like

- The card carries a **stack** row, filled from `ranking["stack_fit"][offer_id]`, never
  composed by a model. Placed with the facts, before the "what matters" line.
- An offer with no fit carried, and an offer whose verdict is `unknown`, both say so in
  words. Leaving the row out would make silence look like a match (T219 spec R9).
- A `mismatch` reads as one: the technologies in `missing`, `weak` and `averse` are
  named, not counted.
- `stack_fit.summary_line`'s hard-coded es/en labels move to `strings/catalogue.json`,
  so `presentation.untranslated()` covers them in every catalogue language
  (`ca` included).
- `render()` takes the ranking's `stack_fit` through the same path it already uses
  for explanations.

## Tests to write first (failing)

In `tests/test_presentation.py`:
- a card for an offer with a `mismatch` fit shows each missing technology by its
  advert spelling;
- a card for an offer with no carried fit shows the "unknown" wording;
- `untranslated("ca")` is empty with the new keys added.
