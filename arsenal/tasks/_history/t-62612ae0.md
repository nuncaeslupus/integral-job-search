`ListPage.url_pattern` admitted exactly one placeholder, `{page}`, so a board's
query was whatever the YAML author happened to write. Measured on the shipped
library before this task:

```text
tecnoempleo_es  https://www.tecnoempleo.com/ofertas-trabajo/?te=python&pagina={page}
jobfluent_es    https://www.jobfluent.com/es/empleos-barcelona?page={page}
trabajos_es     https://www.trabajos.com/ofertas-empleo/atencion_al_cliente
```

Every candidate searching Spain got Python ads and customer-service ads,
whoever they were and whatever they did. Nothing in `constraints.json` recorded
what job the candidate wanted either, so there was nothing to substitute even
if the slot had existed — the aim was absent from both ends.

This is the silent-wrong-answer shape rather than the empty-result shape: the
board returns real, current, well-formed offers, the pipeline ranks them, and
the page looks exactly like a search that worked.

## What this changes

1. **`{query}`** joins `{page}` as an allowed literal in `url_pattern`, and
   nothing else: the brace check still refuses `{0.__class__}`, `{query!r}`,
   `{}` and `{QUERY}`, so the `str.format` injection class the original
   one-placeholder rule closed off stays closed. Substitution is
   `str.replace` with `quote(query, safe="")` — one encoder, correct in a path
   segment and in a query string alike.
2. **A board that asks what to search for is not searched for nothing.**
   `build_list_urls` raises rather than substituting an empty string, because
   an empty query fetches the board's unfiltered list and presents it as the
   candidate's search.
3. **`accepts_query(connector)`** reports whether a board has a slot at all.
   `getmanfred_es` returns its whole active list and is filtered afterwards —
   that is not a defect, but "searched for what you asked" and "returned
   everything it had" are different results and a caller that cannot tell them
   apart will describe the second as the first.
4. **`candidate.Aim`** records the terms. Deliberately **not** in
   `FIELD_MODELS`: D-20's `unfilterable_stated_constraints` says a pinned
   constraint nothing filters on is a lie, and the aim filters nothing — it
   steers the fetch, upstream of the offer set the hard filter narrows.
   Registering it would have meant either a checker that never vetoes (the
   exact silence that gate exists to catch) or a text match whose failure mode
   is the wrong *removal*: "Data Engineer" does not contain "ingeniero de
   datos", and nobody ever learns about the ad the filter ate.

## Which boards were actually parameterised, and why only two

Live, 2026-09-05, differential — the same connector fetched with two queries
and the results compared:

| board | param | verdict |
|---|---|---|
| `tecnoempleo_es` | `te` | **wired.** python 30 cards, "ingeniero de datos" 27, "product manager" 29, titles matching each |
| `jobfluent_es` | `q` | **wired.** different first cards per query, titles matching |
| `trabajos_es` | `BUSCAR` | **not wired** — param accepted and ignored, byte-identical 40 items for both queries |
| `ticjob_es` | `keywords` | **not wired** — GET returns 3 and 2 items whose titles do not match the terms; the board's real search form is a POST |
| `infojobs_es` | — | **not wired** — no form inputs in 1.2 MB of response; JS-rendered |
| `getmanfred_es` | — | no slot by design; the API returns the whole active list |

A connector is only wired when a differential fetch proves the board filters.
Guessing a parameter from a form's `name` attribute is how `ticjob_es` would
have acquired a query slot that quietly returns the wrong three ads.

## Acceptance gate

```bash
set -euo pipefail
uv run pytest tests/test_connectors.py tests/test_candidate_attributes.py -q
uv run python - <<'PY'
from pathlib import Path
from integral.connectors import accepts_query, build_list_urls, parse_connector

steerable = []
for package in sorted(Path("connectors").iterdir()):
    yaml_path = package / "connector.yaml"
    if not yaml_path.is_file():
        continue
    connector = parse_connector(yaml_path.read_text(encoding="utf-8"))
    if not accepts_query(connector):
        continue
    steerable.append(package.name)
    url = build_list_urls(connector, page_count=1, query="ingeniero de datos")[0]
    assert "{query}" not in url, package.name
    assert "%20" in url, f"{package.name}: query not percent-encoded"

assert steerable, "no shipped connector takes a query — the aim is baked in again"
print(f"connectors_steerable_by_the_candidates_terms = {len(steerable)}: {', '.join(steerable)}")
PY
```
