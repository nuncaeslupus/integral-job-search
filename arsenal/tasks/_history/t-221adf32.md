Captured during a test session at step `sourcing` (ledger `test-2026-08-20-a`).

> You should offer to create the InfoJobs connector or similar, or don't we yet have that part
> implemented?

State of play: `connectors/` holds exactly one package, `examplejobs_es`, whose own header says
`examplejobs.test` is not a real job board. `integral.connectors` was never called during the
session. Sourcing fell back to a generic `WebSearch` plus two `WebFetch` calls.

`step-07-sourcing` must say this plainly when no connector covers the candidate's market, and offer
the two real options: build a connector for a named portal, or drive the candidate's own browser
session (which the skill already describes for authenticated sources).

Addressed in: `step-07-sourcing`, `connectors/`.

## What was built

**The disclosure is a rule with a remedy attached.** `status/spec-v2-steps.md` §7 now requires it,
and `step-07-sourcing` carries a `## Coverage` section: state the absence before the results, then
offer the two things that exist — build a connector for a portal the candidate names, or drive
their own browser session on a source they are logged into. A disclosure naming no way out is a
dead end, so both remedies are part of what is measured, not decoration around it.

**An example is not coverage.** `assess_coverage` counts a package only when it declares the
candidate's market *and* its site is not under a reserved TLD (`.test`, `.example`, `.invalid`,
`.localhost` — RFC 2606 and RFC 6761). That is why `examplejobs_es` reports `example_only` rather
than covering Spain, and unlike a blocklist it stays true for the next example somebody commits.

**A search result stays legible as one.** `build_search_offer` is the only path a web-search hit
has into the store and always stamps `source: web_search`; `Connector` refuses that name, so no
connector can claim it from the other side. `offer_provenance` reads the record back and answers
`connector`, `search`, or — the third answer, and the one the defect needed — `unattributed`.

## What measures it

`undisclosed_connectorless_sourcing` counts the sourcing situations in which this tool would fetch
without a connector and say nothing: every market the installed library declares, plus the market
no package declares at all, so the rule is exercised even on a day when every named market happens
to be covered. A library that cannot be read records `-1`, never a clean `0`.

The reading lives in `src/integral/connector_coverage.py`. It was confirmed to fail against the
state D-16 was filed in — `test_a_skill_that_stops_disclosing_fails_the_gate` strips the skill's
Coverage section and asserts the count goes positive, so a zero means the check would notice the
defect returning rather than that a regex matched something.


The `bash` block regenerates the measurement and runs the behavioural half; the `gate` block
asserts the number in the file. Neither alone is the gate: without the first a stale evidence file
passes unchallenged, and without the second a command that exits 0 counts as a gate whether or not
it checked anything.
