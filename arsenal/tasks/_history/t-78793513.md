Promoted from the candidate sessions of 2026-09-06..2026-10-16: a practice the assistant ran by hand (scratch scripts or profile conventions) that any candidate needs.

Nearly every ATS asks free-text questions (why us, notice period, salary expectation, work permit, where you heard of us), often with a character limit. Each time, the session drafted them by hand into a `Form-Answers.txt` beside the documents.

Make it a step-11 output: answers drafted from store entries only (each answer cites its evidence ids, the same way the letter's authorship table does), shortened to a stated character limit, story-bank episodes under the usual per-use approval, staged in `send/` with the rest of the payload.

Suggested gate: `form_answers_without_a_store_source == 0`.

## Acceptance gate

`form_answers_without_a_store_source == 0`, measured over a constructed corpus of
clean answers (a notice period, a salary, a permit, a motivation, an approved story
episode), with nine probes that must each be refused: no citation, an unknown id, a
retracted row, a reaction row, an unrelated row, a story without per-use approval, an
answer over its stated limit, a denial and a number the cited words do not hold. The
module exits 1 on a sourceless answer or a misjudged probe and 3 if nothing ran; the
tests then pin the shortening, the staging into `send/` and the refusals after drafting.

```bash
uv run python -m integral.form_answers && uv run pytest tests/test_form_answers.py -q
```
