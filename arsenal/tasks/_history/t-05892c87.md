Captured during a test session at step `constraints` (ledger `test-2026-08-20-a`).

> About "falso autónomo", this is a bad thing, not something someone wants to work of. Maybe you
> should have asked: "Are you autónomo?", or rather, given he is looking for a job, "Would you
> consider to become autónomo or you prefer payroll?"

The session asked whether the candidate would take work "as autónomo/falso autónomo". Falso autónomo
is an illegal arrangement, not an employment mode on a menu. The `employment_mode` question must be
phrased as a status check or a preference, never as an option being offered.

Addressed in: `step-02-constraints`.

The number is measured over the step-skill library itself — the prose that is
actually put in front of the model — rather than over a restatement of the rule.

It counts a skill as **offering** an unlawful arrangement on either of two
limbs. The first is the obvious one: prose naming *falso autónomo* without
ruling it out. The second is the limb that makes the gate bite, because the
first would have read `0` on the day this happened: the skill that must leave
`employment_mode` resolved carries no rule constraining how that question is
put, so the phrasing is left to improvisation — and improvisation is what
produced the offer. Silence is the defect, so silence is counted.

Verified by reverting the skill edit: `test_no_skill_offers_falso_autonomo_as_a_choice`
and `test_employment_evidence_matches_measure` fail, and the other 24 pass.

**Review round (Qodo, PR #100).** Three real defects in the first cut of the
measurement, all fixed with a test that fails against the pre-fix code:

1. *The prohibition check was satisfied by a bare negation.* `"not "` and
   `"no "` were prohibition markers, so "it is illegal, but not ideal" — a line
   that states the law and then refuses nothing — read as **licensed**. The
   lukewarm mention the module's own docstring promised to reject was admitted
   by the combination it claimed would reject it. Now a word-boundary pattern
   over phrases that forbid an *act*.
2. *The count read a clean `0` when the silence limb measured nothing.* A
   rename of the `constraints` artefact or the `employment_mode` field leaves
   no owning step, and `len(offenders)` was still `0` — a measurement at its
   healthiest-looking the moment it stops happening, which is the failure this
   repo keeps re-learning. `-1` now, which no `== 0` gate can pass.
3. *`UnicodeDecodeError` is a `ValueError`, not an `OSError`*, so undecodable
   prose crashed `probe`/`measure` instead of being recorded as a reason.

The fourth finding — test names not matching
`test_<what>_<condition>_<expected_result>` — was declined: every test in this
file and across the suite uses the narrative form, and Qodo's own relevance
note records prior PRs (#77, #16, #17) rejecting the same rename.

## What the spec requires

`EmploymentModeName` is `Literal["employed", "contracting"]` — two modes, both
lawful. The lawful set is already settled in data; *falso autónomo* is not in
it, and never could be. `.claude/skills/step-02-constraints/SKILL.md` requires
every constraint field to end the step `stated`, `declined` or `unknown`, never
blank — so the employment-mode question is one the step must ask.

## What the code does

The skill listed what to cover — residence, authorisation, languages, hours,
pay floor, mobility, notice — and employment mode was not among them, while the
field it fills still had to be resolved. Nothing said how to ask it, so the
session improvised "would you take work as autónomo/falso autónomo": an
illegal arrangement offered as a mode the candidate might want.

## The fix

The skill now names employment mode in its coverage, states that it is asked as
a status or a preference between the two recordable modes, and carries an
explicit rule that *falso autónomo* is never put to a candidate as a choice —
it may be asked about as something happening to them, and named when warning
them off an advert.

`jobsearch.employment_mode` measures it. It is a module of its own rather than
a flag on `step_skills` because `make evidence` runs each module once with no
arguments: a gate reachable only behind a flag is a gate whose drift nothing
notices — which is already true of D-4's and D-7's numbers today.

## Tests

`test_no_skill_offers_falso_autonomo_as_a_choice` in `tests/test_step_skills.py`
— the gate over the committed library. It asserts the count *and* that the
owning skill carries a licensed prohibition, so the gate cannot be satisfied by
a library that simply never mentions the subject.

`test_an_owning_skill_that_says_nothing_is_counted` — the silence limb, i.e. the
exact pre-fix state. `test_naming_the_arrangement_as_a_choice_is_counted` — the
phrasing the live session used. `test_a_lukewarm_mention_is_not_a_prohibition` —
"not ideal" refuses nothing, so it licenses nothing.
`test_an_unloadable_step_list_records_minus_one_never_zero` and
`test_no_owning_step_records_minus_one_never_a_clean_zero` — a gate that could
not run must not read as a clean pass, on either route.

`test_stating_the_illegality_without_forbidding_it_licenses_nothing` — the
false-licence the first cut admitted.
`test_undecodable_prose_is_recorded_as_a_reason_never_raised` — the decode
failure that crashed rather than recorded.
