Defect (observation O-B from the round-4 second reader on PR #461, T171, non-blocking there
because it is pre-existing and wider than that PR): a probe capture whose `url` is not a
parseable URL makes an evidence gate raise out of `measure()` with a traceback, instead of
reporting that package by name as a finding.

- `src/integral/pagination_capture.py`'s `query_keys` calls `urlsplit(url)` with no guard —
  raises over the whole population (every package with a capture, not only the steerable
  ones).
- `src/integral/query_capture.py` has the identical hole in `_normalised_path` and
  `_slot_components`. (Originally scoped out here as "landing via the still-open PR #461,
  not yet on `main`" — wrong by the time this PR was opened: #461 had already merged as
  `2ef21b0f`, so the identical hole sat live and untracked on `main`. Caught by the second
  reader on this PR's own #497; fixed here rather than filed as a follow-up.)
- `src/integral/connectors.py`'s `_employer_slot_problem` already guards this exact pattern
  (try/except `ValueError` around `urlsplit`, added by the second reader's finding N6 on
  PR #445). Extract that guard into one shared helper `_employer_slot_problem`,
  `pagination_capture.query_keys` and `query_capture`'s two functions all read — the way
  T175 made `DOT_SEGMENTS` one constant both URL builders read — rather than re-spelling the
  try/except a third and fourth time.

A crash is fail-closed (the gate exits non-zero), so this is a legibility defect rather than
a hole: the run names a traceback where it should name the package.

Pin with a fixture package whose `probe/captured.json` carries an unparseable `url` (e.g.
`https://[::1/jobs`), mutation-verify (revert the guard, watch the new test go red), fresh
subprocess per measurement, `src/**/__pycache__` cleared between runs.
