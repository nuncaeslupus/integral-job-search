## What this is

`claude-arsenal` v1.0.0 is a Claude Code **marketplace**. Installing it gives a
project two plugins (`skill-workshop`, `core`) out of
`~/.claude/plugins/cache/`, so the repo no longer needs to carry upstream's tree
at all. This retires `vendor/claude-arsenal` and everything built on it.

## Why now

The v0.36.1 → v1.0.0 subtree pull conflicted on seven files, and the Makefile
already documents why: a squash merge drops the `git-subtree-split:` trailer, so
the next pull replays from a stale base and conflicts on files that carry no
local edits by construction. The standing resolution is "take upstream's tree
verbatim" — a ceremony performed every upgrade to reconcile a copy nobody edits.
Dropping the subtree removes the whole class.

## What changes

- `vendor/claude-arsenal/` deleted.
- `make verify-subtree`, `arsenal-remote`, `arsenal-upgrade`, `update-skills`,
  `assemble-bundle` retired, with `tools/verify_arsenal_subtree.py` and
  `tests/test_arsenal_subtree.py`.
- **`host-gate` becomes four targets**, so `CLAUDE.md`'s block and
  `tests/test_plan_v2.py`'s `_FIVE` move with it. D-22's `integral.repo_gate`
  checks those two agree, and it is what makes this safe to change.
- `claude-arsenal/` — the assembled bundle — **stays**. Upstream v1.0.0 still
  prescribes it, and every protocol step calls into it. It is refreshed from the
  installed plugin's `init` assets rather than from the subtree.

## The open question this task must answer, not dodge

**S10's `skill_listing_budget_overage_chars` currently measures
`.claude/skills/`, which today holds 19 vendored arsenal skills alongside the 14
this repo owns.** Once the arsenal skills come from a plugin, that scan counts
only the repo's own — while the listing they cost context in is unchanged. A
budget of 13,000 measured against ~5,000 of host skills is 8,000 of phantom
headroom, which is a gate getting weaker without saying so.

The resolution is to make the split explicit rather than silent: this repo
budgets the skills it owns, upstream budgets the plugins it ships (v1.0.0's
`make audit` prints a per-plugin listing-budget breakdown). **Do not leave the
budget at 13,000 against a smaller library.**

Measured on the day of the split:

| | skills | description chars |
|---|---|---|
| host-owned (`step-00`…`step-12`, `test-mode`) | 14 | 3,671 |
| arsenal (moving to the `core` plugin) | 19 | 7,028 |
| total, against a 13,000 budget | 33 | 11,241 |

So `listing-budget` becomes **5,000**: round, 1,329 chars of headroom, and not
fitted to the measurement. 4,000 is refused by `check_declaration` — 329 chars
is under `MIN_HEADROOM_CHARS`.

**One assertion stops being true and must not be forced.**
`test_the_evidence_still_reports_the_overage_against_upstreams_default` asserts
`overage_against_upstream_default > 0`, on the premise that this repo is over
upstream's 8,000 deliberately. At 3,671 the host library is comfortably *under*
it, so the overage is 0 and the premise is gone with the skills it was about.
Rewrite the test to say what is now true — the host share is under upstream's
default, and the plugin share is budgeted by upstream — rather than keeping a
`> 0` that only passes while something is wrong.
