## What this is

The decision recorded in `docs/distribution.md` §2, made mechanical.

Today the per-user tree of process spec §6 is `profiles/<handle>/` relative to
the repository root, kept out of git by a `.gitignore` line. That is a
convention. This replaces it with a resolver:

- the store root is `$INTEGRAL_HOME`, defaulting to `~/.integral-job-search/`
  (respecting `$XDG_DATA_HOME` where it is set);
- **the resolver refuses to return any path inside a git work tree** — it walks
  up from the candidate root looking for `.git` and raises rather than
  returning. `--dev` (or `INTEGRAL_DEV=1`) is the single, explicit escape, for
  work on the tool itself;
- every call site resolves through it. A module that builds a profile path by
  string concatenation is the failure this task removes, so the test suite
  points the resolver at a temporary git repository and proves the refusal
  rather than trusting the call sites.

`.gitignore` keeps `profiles/` ignored regardless — two mechanisms for one
promise, the cheap one behind the enforced one.

## Why it is worth doing before anything else in M4

Every module that touches the store gains a call site (`identity`, `profile`,
`cv_store`, `session`, `offers`, `revision`, `retraction`). The cost of the
change grows with the store, and the property it buys — candidate data cannot
reach a repository — is the one this project cannot retrofit after someone
other than the owner has installed it.
