## Acceptance gate

```gate
ontology_hit_rate >= 0.85
evidence: status/evidence/T17.json
key: ontology_hit_rate
status-key: ontology_status
```

```bash
uv run --extra dev pytest tests/test_ontology_health.py -q
uv run --extra dev python -m integral.ontology_health
```

`status-key` is what makes this task honest while it waits: until a concept
source can report an unmapped concept, `integral.ontology_health` records
`ontology_hit_rate: null` beside `ontology_status: "unmeasured"` and
`gate_evidence.py` exits 3 — "the check ran, and what it found is that this
cannot be scored yet". Not a pass and not a fail, and it is the state this task
is in on the day it is filed.

## Why this is its own task

Split out of T17 (`lo-5db0`) 2026-08-22, on D-12's precedent. T17 built the
counting and can show it discards nothing — `discarded_concepts == 0` over 828
concepts from 84 real adverts — but not that the model covers the market,
because the only committed source was read by a pass handed the dimension list.
Its 828 mapped and 0 unmapped is a property of the briefing, not of the ads.

## What has to change before this can be measured

A read pass over a corpus wide enough to fall outside the model, allowed to name
what it cannot map. That is the two deps:

- **T25 (`lo-1af2`)** broadens the corpus past remote programming to ≥6 job
  families. **D-19 (`t-e6546af7`) already measured why this matters**: 0 of 25
  dimensions settle on a construction advert.
- **T26 (`lo-9e41`)** widens the dimension model against that corpus — and
  `ontology_hit_rate` is the number that says whether the widening worked.

The regenerated `corpus/labelled/suggestions.json` must carry a top-level
`unmapped` key; that key is how a source declares it *could* have recorded an
unmapped concept. `ontology_health.read_suggestions` already counts an entry
that names no dimension as unmapped, identified by its quote.

## What it must not become

**Do not make the number appear by narrowing the denominator.** Dropping the
concepts a reader could not name, or re-briefing the read pass with the
dimension list to keep the ratio clean, both produce 0.85+ without producing
coverage — and leave the project with no staleness signal at all, which is the
one thing `status/specification.md` §5.3 says this metric exists to prevent.

## Tests

`test_unmapped_concepts_are_counted_not_discarded` in
`tests/test_ontology_health.py`, extended to the widened model — no job family
below the rate, once a family can be told apart in the source.
