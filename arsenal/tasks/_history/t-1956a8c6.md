## Acceptance gate

```gate
trait_dimensions_ready >= 4
evidence: status/evidence/T26b.json
key: trait_dimensions_ready
```

```bash
uv run --extra dev pytest tests/test_dimension_content.py tests/test_dimension_side.py -q
uv run --extra dev python -m integral.dimensions --traits
```

The two blocks do different jobs and both are required. The `bash` block
regenerates `status/evidence/T26b.json`; the `gate` block asserts the number in
it against the threshold. Without the first, a stale or hand-written evidence
file passes unchallenged; without the second, a command that exits 0 counts as a
gate whatever it measured.

The default command fails on purpose. A task whose measurement is undefined has
not passed its gate — it has not been measured. Replace it as part of the work.

## What this is

Job (2) of T26 (`lo-9e41`), split out and standing on its own. T26 is cancelled;
see its file in `_history/` for why.

Four dimensions with `side: candidate_trait`:

- **creativity**
- **ambition**
- **learning orientation** — do they study their field outside work
- **spare-time engagement**

They carry **no cues** and are **elicited only**: the interview (T27) is their
sole source. `dimensions/README.md` already names this side and says the loader
*refuses* a cue on a trait rather than warning — a cue would assert that an ad's
wording evidences the *candidate's* ambition, when it evidences the employer's
prose.

## Why this is not blocked, and why it is not T26

T23 (`lo-680d`, merged) built the whole `side` machinery. A trait dimension
without cues already loads, one carrying cues is already rejected, and
`dimension_extractor_coverage` already counts only ad-side dimensions. Nothing
here waits on anything: the model has **zero** trait dimensions today, and
`test_the_committed_model_is_all_matched_and_unchanged` asserts exactly that.

What this task is *not* is T26's job (1) — widening the matched dimensions over
the broadened corpus. That was retired by the owner's 2026-08-19 scope change:
dimensions are coined when a live session turns one up, not by a corpus sweep.
And T26's gate, `ontology_hit_rate >= 0.85`, is `unmeasured` today and is T57's
(`lo-7c14`) to make measurable. Neither problem touches these four.

## The gate is one number on purpose

`trait_dimensions_ready` counts the `candidate_trait` dimensions that are
**complete**, not the ones that exist. A dimension named in passing and left
without rungs has no class set for anything to score — the scope-change note on
T26 says so outright — so a half-built one must not count toward the floor.
Complete means all four of:

- `side: candidate_trait`
- declared `levels` (the rungs)
- three-language labels (`en`, `es`, `ca`), as every committed dimension has
- at least one elicitation question

Folding the floor and the well-formedness into one number keeps the gate a
single assertion. Four ready dimensions is the threshold; four malformed ones
score zero.

## Do not

**Do not give a trait evidence from an ad.** D-2 (`lo-77a6`) is the
gold-provenance problem these must not inherit: a trait has no ad text to mine,
so its evidence is episodes from the story bank, never cue hits. This is
distinct from the loader's cue refusal — that stops a cue being *declared*; this
is about where a score's evidence comes from once one is elicited.

**Do not write elicitation questions as self-ratings.** `docs/METHODS.md` §2.1 is
behavioural elicitation: "tell me about a time…", not "rate your ambition out of
ten". §2.1's whole claim is that the second measures what someone believes about
themselves. The existing `team_autonomy` and `social_intensity` files are the
worked examples — both already point their `methods_ref` at that section.

## Consequence to expect

`test_the_committed_model_is_all_matched_and_unchanged` in
`tests/test_dimension_side.py` asserts `{d.side for d in dimensions} ==
{"matched"}`. Landing these four makes it fail **correctly** — it is a claim
about a model that had no trait dimensions yet. Update it to assert the sides
present rather than deleting it; the property worth keeping is that `side` stays
additive and `side_violations` stays empty.
