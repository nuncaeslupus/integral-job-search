Filed from a candidate session (test-mode 658fcce2).

## What happened

A candidate asked for the whole list of applications they had sent, then for a fuller one: what
each advert asked for, what they hold, what they lack. Nothing in `src/integral` produces either.
The session answered with a scratch script that read `applications/*/status.json`, `sent.json`
and the stored offer, plus a hand-written notes file for the fit columns, and wrote one HTML page.

## What is missing

- A command that renders every application a candidate has sent as one page, regenerable on
  request: employer, role, date sent, status, status at source and when it was last seen, the
  advert link and the tracking link.
- A stored place for a tracking URL the candidate reports later. `sent.json` is immutable once
  written, so a link learned two weeks after sending has nowhere to go.
- The fit columns (asked / holds / lacks or not on record) drawn from the extraction and the
  generation manifest, not typed by a model per candidate. "Not on record" stays distinct from
  "lacks": the profile being silent is not the candidate being unable.
- A home for it in the profile tree. `approval.sends_without_confirmation` rglobs
  `applications/**/*.json` and flags any file without `offer_id`/`version`, and
  `revision._CLASSES` reads an unplaced top-level folder as `authored`. The scratch version
  wrote beside the profiles tree to avoid both.
- Two sent dates: applications recorded only by status carry the day they were noted, not the day
  they were sent. The board has to say which one it shows.

## Depends on

The page uses the shared style from T241 rather than its own stylesheet.
