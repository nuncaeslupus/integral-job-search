`es.talent.com` is an aggregator: it republishes adverts from ATSes this library
already reads one-by-one (Workable, Teamtailor, Greenhouse) *and* from feeds it
has no other route to. A nationwide `python` search returns 15 cards whose
employers include boards this repo does not connect at all, so it widens ES
coverage rather than duplicating it.

Its `robots.txt` is one `User-agent: *` group — **no `ClaudeBot`, `GPTBot` or
any other named-agent group at all**, so CLAUDE.md's `restated_for_every_named_agent`
trap cannot apply here: there is no named agent whose omission could be read as
a permission. The `*` group disallows `/search-jobs/*`, `/ajax/*`,
`/services/api-new/search`, `/redirect*`, `/convert*` and `/*.shtml`; it does
not disallow `/jobs` or `/view`, which is all this connector reads.

**The adjudication is the part worth getting right, and the skill's own script
gets it wrong.** `.claude/skills/connector-new/scripts/query_board.py` consults
`urllib.robotparser` and reported `standing: single_parser` — "the reader ran
and could not refuse". That was the correct answer for the default reader
*before T120*. `connector_policy.DEFAULT_SECOND_READER` is now
`integral.second_reader`, a longest-match reader, and on these same bytes it is
`competent`: 68 of the 68 paths RFC 9309 refuses come back False, with **zero
false allows and zero false refusals**. So the honest standing is
`two_parsers_agreed`, and recording `single_parser` on the script's say-so would
have understated the record and moved two committed counts that do not need to
move.

That is this repository's own "a check pinned against a proxy for the property"
family, one level up: the proxy was *a script that names a second reader* rather
than *the second reader the record is verified against*.
