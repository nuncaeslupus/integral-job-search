T172 (#462) settled that an offer's `source_kind` is **declared** in
`connector.yaml` and never inferred from the list `url_pattern`'s `{employer}`
slot. The second reader's F1 is why: a job board's company page —
`https://www.indeed.com/cmp/{employer}/jobs` — takes the same slot, and reading
the slot as "the employer's own board" reports a job board's results as the
employer's own. `dedup.py`'s T75 comment says the kind is *"declared … a
connector's own metadata"* and *"never guessed here from a URL"*.

The same reader found the assumption still standing one file away, in T144's own
gate. `employer_boards.measure` selects what it counts with
`if EMPLOYER_PLACEHOLDER not in pattern: continue`, so that same company page —
passing the T53 contract pack, with a robots row for its host — counts towards
`ats_host_connectors_conforming >= 5`. The floor would then be cleared by
packages that are not ATS hosts.

**Both conditions, neither alone.** A package counts when it carries the slot
**and** declares `source_kind: employer`:

- the slot is what makes one package reach thousands of employers, which is
  T144's whole economy — a single employer's careers page is not an ATS host;
- the declaration is what makes those boards the employers' own.

A package that is an ATS host and forgets to declare drops the count below the
floor rather than inflating it, which is the direction this should fail in.

Three fixtures, each the real `lever_en` package keeping its contract pack, its
host and its robots row, and losing exactly one thing. Each is
mutation-checked, in a fresh subprocess:

| Fixture | Mutant it kills |
|---|---|
| the declaration removed | `if EMPLOYER_PLACEHOLDER not in pattern` — the defect |
| `{employer}` replaced by one employer's slug | the slot requirement dropped |
| declared `aggregator` | any declaration accepted, not `employer` |

The gate keeps T144's floor: `ats_host_connectors_conforming >= 5` still holds,
because the five committed ATS packages declare `source_kind: employer`.
