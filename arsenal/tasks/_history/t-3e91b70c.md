## Acceptance gate

```gate
verified_gate_defects == 0
evidence: status/evidence/T121.json
key: verified_gate_defects
```

```bash
uv run --extra dev pytest tests/test_verified_gate.py -q
uv run python -m integral.verified_gate
```

## Why this exists

The account spent its **2000 monthly GitHub Actions minutes in four days** and ran
dry on 2026-09-04. Runs still start and still fail, in single-digit seconds with
unreadable logs. `merge-policy` is `after-ci-and-review`, so half the policy has
no enforcer until the period turns over.

`make host-gate` runs exactly the four checks CI ran, which makes it the obvious
stand-in. Run in a session's own checkout it answers a **weaker question**:

- CI measured the **pushed commit**. A local run measures the working tree, which
  can carry uncommitted edits, a staged-but-uncommitted file, or a stale `.pyc`
  whose source was restored inside the same second — see `CLAUDE.md`, "A reverted
  mutation can leave the mutated bytecode running", which is a real trap met on
  #329.
- CI's verdict named the commit it tested. A local verdict is whatever the session
  says it is. On 2026-09-04 the tested-equals-merged property was checked **by
  hand, twice**, on #329 and #319 — exactly the kind of step that gets skipped the
  third time.

## Scope

- `tools/verified_gate.sh` — resolve a ref to a 40-character SHA, check **that
  commit** out into a throwaway detached worktree, clear bytecode, run
  `make host-gate` there, print a verdict block naming the commit, remove the
  worktree.
- It **delegates** to the aggregate target and never lists targets. A listed
  subset is a second definition of the gate, free to fall behind the Makefile,
  which is D-22's subject one layer out.
- `integral.verified_gate` asserts the script still does all of that, and that
  `CLAUDE.md` names it. Prose naming no script, and a script no prose names, are
  the two halves of D-22's original defect.
- Fix the trigger that made every pull-request push run the whole suite **twice**
  (`on: push: branches: ["**"]` beside `on: pull_request`, in concurrency groups
  that cannot collapse because `github.ref` differs between the two events).

## The zero must hide nothing

`verified_gate_defects` is a sum, so each component is reported beside it by name:
`host_gate_targets_not_run`, `missing_properties`, `undocumented`. A metric reading
0 while a reader cannot see *which* properties were checked is the shape this
repository has caught four times — `status_is_asserted` (T108),
`incidental_duplicate_drops` (#323), `negation_recall_hits_by_mechanism` (#318),
`robots_adjudications_without_a_competent_second_reader` (T116).

The denominator is a floor — `verified_gate_contracts_at_least`, over contracts
since the redesign — and it is written as a **literal**, exactly as
`naming.MINIMUM_SCANNED` is. The sentence here used to say
the opposite — "compared against the declared table rather than written as a literal
that can drift from it" — and the first implementation did what that sentence said:
`MINIMUM_PROPERTIES = len(REQUIRED_PROPERTIES)` compared against
`checked = len(REQUIRED_PROPERTIES)`, which is `x < x`. The guard was unreachable,
its `return 3` was dead code, and deleting half the table moved both sides together.
A floor a table can drag is not a floor. (Second-reader report on #333, F3.)

## Reading the script's text was tried three times, and defeated three times

**This history is the argument for the design below, and it is recorded here
because a future session that does not know it will "simplify" the contract table
back into a dozen regexes.** Each round below passed its own gate.

- **Round 1** searched the whole file for `make\s+host-gate`. The script's own
  header comments contained it twice, so a script whose run line said `make lint`,
  and a script with the gate deleted and `status=0` hard-coded so every verdict
  printed PASS, **both** scored `verified_gate_defects == 0`.
- **Round 2** (`316cd6c`) added `executable_text()` — a filter dropping
  comment-only lines — and grew the table from 5 patterns to 12.
- **Round 3** defeated round 2 twice over. **A1**: all twelve patterns inside one
  unused single-quoted string `dead_string_never_executed='…'`, beside
  `sha=0000…`, `resolved_from="origin, fetched just now"`, `echo "verdict   PASS"`
  and `exit 0` — `verified_gate_defects: 0`, `properties_checked: 12`,
  `missing_properties: []`, over a script that resolves nothing, fetches nothing,
  creates no worktree and runs no gate. **A2**: the same twelve in *trailing*
  `# …` comments on `true` lines, which the filter keeps because a line carrying
  code is not comment-only. Same zero.

The verifier's diagnosis is the finding, not the two bypasses:

> `executable_text()` is a `#`-line filter, not an executability test. Any inert
> but non-`#` location — a quoted string, a heredoc body, a trailing comment, a
> `case` branch, an unreachable function — satisfies all 12 properties.

**Reading a script's text cannot establish what the script does.** A thirteenth
pattern does not help; a bash parser moves the goalposts rather than the game.
And "more care" is not the alternative — two careful rounds of patterns did not
catch what the third round found in its first five minutes.

## The design that replaced it: behavioural contracts

Note which half had held up. In round 1 the mutation that completely fooled the
text checker was caught by the *functional* test, which ran the real script
against a real repository. **The functional half has never been defeated.** So
the whole measurement is now that half.

`CONTRACTS` is a table of ten named claims about what the script does **when it
is run**. Each builds a throwaway repository in a temporary directory — one of
them a clone with a real bare `origin` — runs `tools/verified_gate.sh` against it,
and reads the verdict block, the exit status and the filesystem afterwards.
`verified_gate_defects` is the number of contracts it fails, plus the one
documentation cross-check.

| contract | the mutation it kills |
|---|---|
| `a_failing_gate_is_reported_as_FAIL` | one line `status=0` after `status=$?`: the gate runs, genuinely fails, and the block prints PASS with rc 0 |
| `the_commit_is_measured_not_the_callers_tree` | running the gate in `${repo_root}` |
| `the_verdict_names_the_commit_it_measured` | a fixed string where the SHA goes |
| `nothing_survives_the_run_pass_or_fail` | deleting `trap cleanup EXIT` — the round-2 property `worktree prune` matched happily while cleanup never ran, and the leak is on the FAILING path |
| `the_resolution_line_is_true` | hard-coding `resolved_from`, which was an echo of a variable nothing constrained |
| `the_origin_reachability_line_is_true` | the same, for `on origin` |
| `caller_relative_refs_measure_the_caller` | the round-2 guard `[ "${ref}" != "HEAD" ]`, a blacklist of one string, which `@` walked straight through |
| `an_unmeasurable_ref_refuses_with_2` | a fall-through to a gate run over whatever tree the script landed in |
| `the_aggregate_target_is_what_runs` | D-22's drift: four real targets in place of the delegation — and running the gate **twice**, which is what `open_task_pr.sh` v3.2.0 did across the archive, because the probe keeps repeats rather than collapsing to a set. Observed through a probe Makefile, never read out of the script |
| `the_verdict_reports_the_command_that_ran` | round 1's compounding half: a block claiming the aggregate while `make lint` ran |

**Measured against the new checker.** A1 scores `verified_gate_defects: 8`, A2
scores 8, where round 2 scored both 0. B1 — the `status=0` line, which no text
property ever touched — scores 2. Every one of eleven mutations in
`tests/test_verified_gate.py::_MUTATIONS` is reported **by the name of the
contract it breaks**, and the same table asserts the unbroken script passes that
same contract: the mutate-verify-restore cycle, committed, running on every
`make test` rather than once in the session that wrote it. Nothing on disk is
ever mutated — the mutated body is a string handed to a temp path — so the stale
`.pyc` trap has no way in.

The two contracts A1 does **not** fail are named rather than rounded up:
`the_commit_is_measured_not_the_callers_tree` is satisfied by an unconditional
PASS, and `nothing_survives_the_run_pass_or_fail` by a script that creates
nothing. Neither is redundant — each is the only contract catching its own
mutation — but neither recognises a do-nothing script alone, and none is claimed
to. A contract table works as a set.

## What still reads text, and what may never again

One thing: `undocumented`, the substring check that `CLAUDE.md` names the script.
That is D-22's prose half — prose naming no script, and a script no prose names —
and it is not a claim about behaviour.

**No contract pins incidental ordering.** Round 2's property 11 required
`fetch\s+--quiet\s+origin\s+--\s`, so a harmless flag reorder was a defect while
a dead copy of the entire table was clean: fail-closed on the cosmetic and
fail-open on the substantive, exactly backwards.

## Two residues of F4, closed in the same round

- `_take_flag` used `args.index(name)` and removed only the **first** occurrence,
  so `--script A --script B` left `B` standing as the positional — the evidence
  path — and the run overwrote it: 4189 bytes down to 232 bytes of JSON, rc 0, no
  warning. A repeated flag is now refused with exit 2.
- `--script=PATH` and any unknown flag began with `-`, so they were stripped from
  the positionals *and* never recognised as flags. `own_tree` stayed True, the run
  measured **this** repository, and it wrote the real `status/evidence/T121.json`
  — a caller who mistypes got a green answer about a file they never named.
  Unknown options, and a second positional, now exit 2.

## What the second reader found, and what now holds it

The first implementation passed its own gate while failing its central claim. The
report on #333 is the record; every finding it accepted is a committed case in
`tests/test_verified_gate.py`, and the property table grew from 5 to 12:

- **F1** — the `make\s+host-gate` pattern was searched over the whole file, and the
  script's own header comments contained it twice. A script whose run line said
  `make lint`, and a script with the gate line deleted and `status=0` hard-coded so
  every verdict printed PASS, both scored `verified_gate_defects == 0`. The command
  is now one `gate_command=` assignment, used by the run line and by the verdict
  block, and every property is matched against `executable_text()`.
- **F2** — `git fetch origin HEAD` succeeds and returns origin's *default branch*,
  and `FETCH_HEAD` was preferred over the local ref, so the no-argument form
  measured `main` and printed PASS from a branch whose gate genuinely failed. Every
  functional test used a repo with no remote, so that branch of the resolution had
  never once run.
- **F4** — `--script PATH` wrote the evidence JSON *over* PATH, because the flag's
  value was left standing as the first positional. The module's own docstring
  documented that invocation.
- **F5** — a missing script recorded `gate_status: "unmeasured"` while `_main`
  returned 1, which says the opposite of what the code decided in the vocabulary
  `make evidence` reads.
- **F6, F7, F8** — three claims corrected rather than restated: the header credited
  `integral.repo_gate`, which never mentions this script; the quoted `verify-gates`
  count was taken pre-archive; and the CI runs cited as the cost were runner-dead
  ones lasting seconds.

## A grep is not a proof — which is why there is no longer a grep

This section used to say "the module reads the script's text; text cannot tell
you the script works, so the *tests* also run it". That split was the defect: the
metric came from the half that could be fooled, and the half that could not was
beside it, uncounted. `verified_gate_defects` now comes from the running half.

The contracts never run the real `make host-gate`: that takes 162 seconds and
proves only that this tree is green, which `make host-gate` already says. They
run against throwaway repositories whose aggregate target is one `echo` or one
`exit 1`, so the whole measurement costs about **1.5 seconds**, and the full
`tests/test_verified_gate.py` — 46 cases, including every mutation — about 13.

One detail that is easy to lose and expensive to rediscover: `git init --bare`
points `HEAD` at `master`, and `git fetch origin @` only answers with a default
branch when the remote has one. Without `git symbolic-ref HEAD refs/heads/main`
on the bare repo, `caller_relative_refs_measure_the_caller` cannot reproduce the
failure it exists for, and passes vacuously.
