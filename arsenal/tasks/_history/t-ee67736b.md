The offer that ended this tool's first complete run — Grafana Labs, Staff AI
Engineer — was not found through an aggregator. It was found by going to the
employer's own posting. The candidate, once it was sent:

> "we finally found the good job when looking directly to companies ads, not
> aggregators. That is a very important point to take seriously. There are
> websites easier to find better results."

Every connector in `connectors/` today points at an aggregator or a job board.
**None points at an ATS host**, and that is the cheap coverage that is missing:
Greenhouse, Lever, Ashby, Workable, SmartRecruiters, Teamtailor, Personio and
Recruitee each host thousands of employers behind **one** URL shape, so a single
connector per host reaches every company on it. Coverage bought as data — which
is the candidate's own stated principle, now in `profile/evidence.jsonl`: *if
something can be added as data, that is better than adding code.*

**This is not T75 and not T91.** T75 makes dedup prefer the employer's copy
**when both copies arrive**; it does nothing to make the employer's copy arrive.
T91 fixes the loop that gives up once the existing connectors are exhausted;
this fixes *which sources exist to be exhausted*. Without it, "the market is
exhausted" keeps meaning "our aggregators are exhausted", which is a statement
about our coverage wearing the clothes of a statement about the market.

Two things ride along, both cheap and both easy to get wrong later:

- **Adjudicate robots per host, once.** One verdict covers every employer on
  that host, so it is worth deciding through `integral.robots` exactly as
  CLAUDE.md requires, and recording a refusal in `connectors/ruled-out.yaml`
  with the distinction that file's header already draws between
  `robots_refused` and `policy_refused`.
- **A sourcing round says where each result came from.** "An aggregator" versus
  "the employer's own board" is a fact worth showing the candidate, because on
  the only complete run so far it is the fact that decided the outcome.

The gate is a **floor, not a count** — T100's reason: an exact package total in
committed evidence drifts on the next connector anyone adds (T111 is that same
defect, still open). Each connector counted must pass the T53 contract pack and
carry a recorded robots verdict, so the number cannot be raised by adding files
that fetch nothing.
