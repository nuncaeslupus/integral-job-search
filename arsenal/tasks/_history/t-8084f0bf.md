Twice the candidate said fintech and e-commerce were not of interest. Twice
more, frontend and cloud. All four kept arriving.

The candidate's own diagnosis is the task:

> Did you search for the ads all together at the beginning or are you adding
> filters with everything I'm telling you?

That question separates the two designs, and from the outside they are
indistinguishable **until the candidate rules something out and sees it again**.
A search executed once and re-sorted looks exactly like a search that learns,
right up to the moment it fails. The candidate reached that moment at step 5 and
lost confidence in the tool: *"Looking for alternatives would have been more
productive and the user would have felt the tool is working."*

**A rank penalty is not an exclusion.** `weights.py` can push a fintech advert
down and it still appears, which is the observed behaviour and reads as not
listening. An exclusion the candidate stated in words has to reach the *query*,
before offers are fetched — the two are different code paths and only one of
them is visible to the candidate.

Note the asymmetry with `stated_constraints.py`, which covers hard constraints
(permit, location, floor). A sector distaste is soft: it should not silently
delete a role that is otherwise a strong match. So the gate is not "never
fetched" — it is that a restated exclusion is either honoured or **named**, with
the reason it survived.

## Acceptance gate

Three, because each passes while the others break.

```gate
restated_exclusions_resurfaced == 0
evidence: status/evidence/T90.json
key: restated_exclusions_resurfaced
status-key: gate_status
```

```bash
uv run --extra dev pytest tests/test_sourcing_exclusions.py -q
uv run --extra dev python -m integral.sourcing_exclusions
```

- `test_an_exclusion_stated_at_cycle_n_shapes_the_query_at_cycle_n_plus_1` —
  the exclusion reaches the request, not only the ranking.
- `test_a_penalised_offer_still_counts_as_resurfaced` — a soft demotion does not
  satisfy the metric, because the candidate still saw it.
- `test_an_exclusion_overridden_by_a_strong_match_is_named_not_silent` — the
  escape hatch exists and is always visible.
