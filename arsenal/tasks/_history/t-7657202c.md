Imported from issue #938

Engine gap found while building a Teamtailor connector (2026-11-12).

## The gap
Teamtailor gives every employer its own origin, `https://<slug>.teamtailor.com`. The `connectors.py` `_employer_slot_problem` check refuses `{employer}` in the host ("in the host each employer is its own origin, and one robots verdict no longer covers them"). That refusal is deliberate (T144, #445), so a package cannot route around it. Any per-subdomain ATS hits the same check (Personio `<slug>.jobs.personio.de`, Recruitee `<slug>.recruitee.com`, BambooHR).

Done means the engine allows a host slot only when **robots is adjudicated per employer origin**: `Robots().allows` is checked against each filled origin at fetch time, and the robots-adjudication row says that the verdict is per origin and not one verdict for the package. That row needs a negative control per origin, or a stated rule. This is an engine change that needs a second reader.

## The route, already measured
- JSON Feed at `https://{employer}.teamtailor.com/jobs.json` (JSON Feed 1.1). It holds every job in one response, so there is no pagination, and `content_html` carries the full body, so no detail page is fetched.
- Item fields: `url`, `title`, `content_html`, and `_jobposting` (schema.org JobPosting): `identifier.value`, `hiringOrganization.name`, `jobLocation.0.address.addressLocality/addressCountry`, and in rare items `baseSalary.{currency,value.{minValue,maxValue,unitText}}`.
- Ruled out:
  - the HTML `/jobs` page, because its theme markup differs per tenant;
  - `/jobs.rss`, because `<link>` is a void element in the parser and `guid` is a UUID.
- robots.txt is identical on the tenants checked. The `*` group disallows `/app/`, `/messages/`, `/messenger/`, `/facebook/tab/` and `/jobs/internal/`. `query_board.py` gave `two_parsers_agreed`, with negative controls `/app/` and `/jobs/internal/x`.
- Employers seen: career (Teamtailor), flanks, leytonglobal-spain, qida, qtech, signicat, tendios.
