## The defect

Found by the second reader on #461 (T171). `connectors.build_list_urls`
substitutes `quote(query, safe="")` into `{query}` and refuses only a blank
query. `quote` leaves `.` alone, so a candidate query of `..` survives whole.
When the slot is in the path, as #455's `infojobs_es` has it
(`…/ofertas-trabajo/{query}/barcelona`), `..` builds
`…/ofertas-trabajo/../barcelona`. RFC 3986 §5.2.4 (remove_dot_segments)
resolves that to `…/barcelona`: a request that carries no query at all, and
whose answer is reported as a search.

The detail builder in the same module (`_templated_url`) already refuses both
dot-segments, for the same reason.

## The fix

`build_list_urls` refuses a query whose encoded form is one of RFC 3986 §3.3's
dot-segments when a `{query}` slot is in the path component. It raises
`ConnectorError`, the same posture as the blank-query refusal. In the query
component `..` is a literal search and is still sent. The dot-segment set is
one constant read by both builders, not spelled twice.
