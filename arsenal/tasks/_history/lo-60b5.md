## Acceptance gate

```gate
feedback_traceability == 1.0
evidence: status/evidence/T21.json
key: feedback_traceability
```

```bash
uv run python -m integral.feedback
```

The two blocks do different jobs and both are required. The `bash` block
regenerates `status/evidence/T21.json`; the `gate` block asserts the
number in it against the threshold. Without the first, a stale or hand-written
evidence file passes unchallenged; without the second, a command that exits 0
counts as a gate whatever it measured.

The default command fails on purpose. A task whose measurement is undefined has
not passed its gate — it has not been measured. Replace it as part of the work.

## The seam this must close (noted by review on PR #27)

T28 shipped `profile_capture.capture_offer_decision_reason`, which wraps
`lifecycle.transition` and routes a decision's free-text `reason` into
`evidence.jsonl`. **`lifecycle.transition` itself still writes nothing**, by
design: coupling the lifecycle to the profile store would cross an ownership
boundary S5 deliberately drew.

That leaves a seam, and it is yours to close rather than T28's: today the only
callers of the wrapper are T28's own coverage driver and its tests, because
**no production offer-decision flow exists yet — you are the task that builds
it.** So this is not a defect in the wrapper; it is the reason `T21` exists.

Two things follow for whoever picks this up:

1. **Route every reason-bearing decision through the wrapper**, not through
   `transition` directly, or `feedback_traceability` will measure a path real
   code does not take — the same "the gate measures the thing built for the
   gate" failure this repository has already been bitten by.
2. **Leaving `transition` callable with a `reason` that goes nowhere is a
   bypass.** Decide deliberately what to do about it — make the wrapper the only
   way to pass a reason, have `transition` refuse one, or accept the bypass and
   say why — and record the decision. Review raised a domain event as a third
   option and judged it beyond T28's scope; it is arguably within yours.

D-8 is a *different* gap and does not cover this one: it is about the captured
row being unable to name **which offer** it was about.

## Scope change — v2 plan, 2026-08-18

Feedback moves **two** things, not one: the weights (through the evidence log
and a rebuild) **and the offer's lifecycle status** (S5). "Not this one because…"
is both an elicitation and a decision point, which is why step 10 is a different
step from step 5 with a different stop rule and a different gate.

What the employer said back is part of the record too — a rejection, a silence
that ran past a stated date, an invitation, an offer, the reason given —
recorded against the application and kept with it.
