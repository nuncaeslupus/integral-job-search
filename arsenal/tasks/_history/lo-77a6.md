## Acceptance gate

```gate
cue_derived_gold_in_evaluation_split == 0
evidence: status/evidence/T3.json
key: cue_derived_gold_in_evaluation_split
```

```bash
uv run python -m jobsearch.dimensions --coverage
uv run --extra dev pytest tests/test_dimension_content.py tests/test_dimension_model.py -q
```

The two blocks do different jobs and both are required. The `bash` block
regenerates `status/evidence/T3.json` and runs the tests; the `gate` block
asserts the number in it.

**Why this metric and not `evaluation_gold_count >= 1`.** The obvious gate —
"there is independent gold to score against" — is one this task cannot satisfy
and must not pretend to: the labelling campaign is retired, the owner is the
only independent reader left, and a task that fabricated human labels to go
green would be committing the exact fraud D-2 was raised to prevent. The
measurable deliverable is the *separation*, not the supply.

So the gate asserts that no cue-derived gold ever reaches the evaluation set.
It is computed by running the real `evaluation_gold` and counting anything in
its output that is not a human label, so it fails the moment that filter is
relaxed — which is a plausible edit, because every list it returns is currently
empty and that reads as a bug. `evaluation_gold_count` and
`dimensions_without_evaluation_gold` are recorded beside it as the honest
statement of what cannot yet be measured: 0 human labels, all 25 ad-side
dimensions unscoreable.

## What the spec requires

`status/specification.md` success criteria: `extraction_macro_f1 >= 0.75`
"against the hand-labelled corpus". METHODS §4.4 defines it as the unweighted
mean of per-dimension F1 — a measurement of whether extraction finds what a
human found, on text the extractor has not been fitted to.

## What the code does

T3 gave every dimension in `dimensions/*.yaml` at least one gold example, and
`dimension_extractor_coverage` (measured 1.0) counts them. Those 56 gold spans
were selected by searching `corpus/raw/ads.jsonl` for text that the dimension's
**own cues** already match, then recording the surrounding excerpt verbatim.

They are real ad text — `verify_gold` proves that byte-for-byte — but they are
not independent of the extractor. Scoring extraction against them measures
whether a regex re-finds the string it was written from, which passes at ~1.0
and means nothing. Left unrecorded, this is exactly the shape of failure the
spec's risk register warns about: a numeric gate that passes while measuring
nothing.

## The fix

1. When T5 (`lo-d2b2`) produces hand labels on the elicitation/evaluation split,
   T15 (`lo-25b1`) must compute `extraction_macro_f1` **only** against those
   labels. The v0 gold set is a smoke test that a cue fires on genuine market
   language; it is not an evaluation set.
2. Either give `extraction.gold` an explicit provenance field
   (`derived_from: cue | human`) so the two can never be mixed by a later
   reader, or move the hand labels to a separate store and have T15 refuse a
   gold example whose provenance is `cue`.
3. Cross-check: any dimension whose only gold is cue-derived at T15 time should
   surface in the T17 `ontology_hit_rate` review rather than passing silently.

## Location

`dimensions/*.yaml` (`extraction.gold`), `src/jobsearch/dimensions.py`
(`GoldExample`, `verify_gold`), and the T15 extraction evaluation when it is
written. Provenance caveat currently documented in `dimensions/README.md`.

## Scope change — the risk moved, 2026-08-19

T5's labelling campaign is retired (see `lo-d2b2`): the owner read part of the
pre-marked corpus, found the read good, and decided the model should read each
advert and find the dimensions alone. That removes the supply this divergence's
fix step 1 assumed — and, more importantly, it moves the failure it was raised
against rather than closing it.

**The old shape.** Gold spans were selected by searching the corpus for text a
dimension's own cues already matched, so scoring extraction against them asked a
regex to re-find the string it was written from.

**The new shape, one layer up.** `corpus/labelled/suggestions.json` was written
by a model reading each advert for meaning, with no cue consulted — that part
holds, and `suggestion_cue_agreement == 0.372` (`cue_unreachable == 520/828`)
measures it rather than asserting it. But the extractor T15 builds is *the same
kind of reader doing the same job on the same adverts*. Scoring it against those
marks measures self-consistency and passes near 1.0 for the same reason the
cue-derived gold did. Independence from the cues is not independence from the
model.

**The only independent reader left is the owner.** So:

1. `extraction_macro_f1` is computed **only** over labels whose `source` is
   `human`, `confirmed` or `edited` — i.e. what a person decided. Cue-derived
   gold and unconfirmed suggestions are both excluded, and the exclusion is by
   construction: neither is a `Label`.
2. **Report `n` beside the number, and floor it.** A macro-F1 over 8 labels on
   one advert is noise wearing a threshold. T15 (`lo-25b1`) must refuse to emit
   `extraction_macro_f1` at all — not emit a low one — until at least `n` human
   labels exist per scored dimension, and must name the dimensions it therefore
   could not score. A gate that cannot be measured yet is unmeasured, not failed
   and not passed. Pick `n` when the labels exist to pick it from; anything
   chosen now is invented.
3. **Agreement between the extractor and `suggestions.json` may still be
   computed, and must never be called F1.** It is a consistency check with its
   own name (`extraction_read_agreement` or similar) and no threshold in the
   spec. Naming it as the gate is the whole failure this task exists to prevent.
4. The blind-control cohort (16 ads, shipped with no marks) is the one slice
   where a human label was formed without seeing a proposal first. It is small,
   but it is the only unprompted human read in the corpus — spend it on
   measurement, not on convenience.

Fix step 2 of the original (`derived_from: cue | human` on `extraction.gold`)
stands unchanged and is now the mechanism that keeps (1) enforceable.
