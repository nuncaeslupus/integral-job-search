T200's annual bound (`connectors._outside_annual_bound`, `salary_recovery._BOUNDS["year"]` = 1,000,000) is blind to currency and is applied to every connector band with `period is None`. Every INR band foorilla_en prints (`INR 1500K-2800K` .. `INR 3700K-5876K`, 11 rows in the fixture) is above it, so in production each INR row that reads its own detail page yields `salary = None` with nothing reported. The fixture cannot see it: its one shared detail page is CAD (second reader, #554 round 2, probe: `salary_rows_read` 104 -> 54 with one detail band changed to INR). `_band_defect` on the recovery route is currency-blind in the same way.

The same task takes the nofluffjobs_en hourly bands, which T200 left as declared refusals (`105 - 115 PLN / h`, `35 - 43 USD / h`; connectors/nofluffjobs_en/fixture/salary.json rows 0 and 2): a `take` that cuts a period out of the card text and a period vocabulary member for `h` (`salary_period.normalize_period` does not accept it), so those rows read as `hour` instead of being refused.

Rules: a bound per currency scale (or per currency), not a wider global one; a refusal that stays must still be declared with its reason; the audit gains the measured key `salary_rows_refused_for_bound_or_period`, which counts refusals whose declared reason names the bound or a missing period, and it goes to 0.
