## Acceptance gate

```gate
evidence_writes_for_a_foreign_library == 0
evidence: status/evidence/T53.json
key: evidence_writes_for_a_foreign_library
```

```bash
uv run --extra dev pytest tests/test_connector_contract.py -q
```

The number is measured over `evidence_target` — the function `_main` actually
uses to decide where a run records — rather than over a restatement of the rule.
That distinction is the whole point here: the corrupted measurement
(`connector_contract_violations`) reads identically whether or not the bug is
present, so a gate phrased in terms of *it* could never see this defect. The
question that separates the two states is "may an invocation that checks
somebody else's library record into ours", and it is asked of the code.

The regression test carries the rest, because the remaining half of the defect
is a side effect on repository state: only an assertion that the committed file
is byte-unchanged after a foreign check can catch a future rewrite that reaches
the same decision by a different route.

## What the spec requires

`docs/distribution.md` §5 hands the contributor this exact invocation, to run
over their own directory, on their own machine:

```bash
uv run python -m jobsearch.connector_contract --connectors <dir>
```

`--connectors` is described as "what makes it the contributor's command as well
as ours: it runs over their directory, on their machine, and reaches the
identical verdict." A verdict is all it promises.

## What the code does

`_main` called `write_evidence(target, directory)` unconditionally, and `target`
defaulted to `DEFAULT_EVIDENCE_PATH` — this repository's
`status/evidence/T53.json` — regardless of which directory was checked. So the
documented contributor invocation silently replaced our committed measurement
with a `packages_checked` about *their* directory.

On a clone the consequences run in this order: `make evidence` regenerates and
reports drift; a session that resolves the drift by committing it writes a false
number into a merged task's evidence; `make verify-gates` then asserts T53's gate
against it. The measurement most likely to be wrong is the one nothing in the
diff explains.

Found by running the documented command once, against a scratch directory, while
investigating D-10.

## The fix

Evidence is written only when the caller named a destination, or when the check
ran over this repository's own library. `measure()` is split out of
`write_evidence()` so that checking a library and recording a measurement about
this repository are two separate acts rather than one.

This is the same shape as the six holes review found on #77 — the checker and
the thing it records disagreeing about what was measured — and the seventh
(D-10), which is the documented shape and the runtime disagreeing.

## Tests

`test_the_contributors_command_leaves_our_committed_evidence_alone` in
`tests/test_connector_contract.py` — all three of the command's exits (3 over an
empty library, 0 over a conforming copy, 1 over a broken one) leave
`status/evidence/T53.json` byte-identical. The empty-library case is the load-
bearing one: it measures 0 packages where the committed file says 1, so a
regression cannot hide behind a copy of our own library measuring the same.

`test_the_gate_still_records_when_the_caller_names_a_destination` — the other
half: suppressing the accident must not suppress the gate `make evidence` runs.

Verified by reverting the fix: the first test fails, the other 49 pass.
