## The defect

A live candidate session on 2026-09-10 sourced for a pharmacy technician /
dermoconsejera in Barcelona with four phrases: `técnico farmacia`,
`dermocosmética`, `parafarmacia`, `farmacia online atención al cliente`. That
session reported 81 offers from the six ES boards and **none** a pharmacy,
parapharmacy or dermocosmetics job. Its run lives in a candidate profile, so
no committed artefact reproduces the count; the committed fact is the category
URL below. The installed ES boards are tech-heavy. The one general
board, `trabajos_es`, pointed at the fixed `atencion_al_cliente` category, so
it handed every candidate the same forty customer-service adverts whatever
they had asked for.

The gap is **sector**, not language (compare the DE/FR/IT/NL/PT finding in
`connectors/ruled-out.yaml`'s `language_unsupported`).

## The fix

trabajos.com has a keyword search, `?CADENA=`, and it answers correctly.
`url_pattern` becomes `https://www.trabajos.com/ofertas-empleo/?CADENA={query}`.
Both halves of the search are committed and read by
`tests/test_connect_portal.py`:

- `connectors/trabajos_es/probe/` is a live capture of `técnico farmacia` on
  2026-09-10: 40 rows, 19 whose title matches `farm|dermo|cosm`
  (case-insensitive), and 15 whose `location_raw` contains `Barcelona`, all read
  by the connector's own `parse_list_page`. It shares no advert with `fixture/`.
- `tests/fixtures/connectors/trabajos_es_no_hits.html` is its answer to
  `zzqxvw`: the page echoes the word in its own search box and yields **zero**
  rows rather than a fallback list, so an empty answer means empty.

The search page serves the same `.listado2014.card.oferta` markup as the
category page `fixture/` was recorded from.

A live run of the changed package over the four phrases (not reproducible
from any committed artefact, so an observation rather than evidence) added 49
offers, dropped none, and fetched all 8 detail pages it needed.

**Caught by the second reader on #447.** The first version pinned only that
`{query}` appeared in the pattern. Swapping `CADENA` for `q`, a key the board
ignores and answers with forty unrelated adverts, kept every test and
`make evidence` green. So the probe was re-recorded from the search itself, and
the pattern must now rebuild the probe's URL exactly.

**And again in round 2.** Rebuilding the recorded URL binds the pattern to the
capture, not to the board having read the term. A pattern on a path that
ignores `CADENA` (`/atencion_al_cliente?CADENA={query}`), with the probe honestly
re-recorded from it, passed everything. So
`test_the_board_searched_for_the_term_the_connector_sends` reads the board's
own answer instead. The probe and the no-hit page each echo the term they
searched for in their `CADENA` box, and the pattern must send exactly that term
and nothing else. Two different terms mean hard-coding one cannot satisfy both.
The same round made the IP-address guard scan every file git lists, rather than
naming directories.

## The survey, recorded

The same session surveyed the pharmacy-sector boards the connector-new skill
names and recorded each in `connectors/ruled-out.yaml` with a retest. Three
boards are readable and each needs an engine change, which the skill says to
file rather than work around in a connector file:

| board | gap |
|---|---|
| farmatalent.com | the advert href is on the list item itself, and field selectors read only descendants |
| infoempleo.com | a query with no hits returns ten fallback adverts in the same `li.offerblock`; a simple selector cannot exclude `.ShortResult` |
| pmfarma.com | the body is only in `api.pmfarma.com/api/oferta/{id}`, and that fetch URL outranks a mapped `url` in `build_offer` |

The rest are out:

- The COFB board needs a login and robots-refuses `/group/guest/`.
- The CGCOF portal is rendered through admin-ajax and lists no Barcelona.
- es.jooble.org and es.indeed.com answer 403.
- opcionempleo.com serves a challenge page, which was not bypassed.
- The robots.txt of jobatus.es and laboris.net cannot be read.

None of the engine changes is in this task. Each touches `connectors.py` or
`sourcing.py`, where T144 is currently changing the list format, so they wait
for it. Each is a row under `blocked_on_engine` in
`connectors/wanted.yaml`, naming the change it needs, to be seeded as a task
once #445 lands.

The count alone is not the pin. A steerable board added elsewhere would keep it
at 3 with trabajos_es reverted, and a key the board ignores keeps it at 3 with
the connector steering nothing. Two tests carry the property:

- `test_searched_and_handed_everything_are_reported_apart` names the steered set
  exactly, so removing `{query}` fails it by name.
- `test_the_probe_was_recorded_from_the_request_the_connector_sends` requires the
  pattern to rebuild the live capture's URL, so sending `q` instead of `CADENA`
  fails it by name. Both mutations were run.
