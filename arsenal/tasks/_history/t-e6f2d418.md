T113's rule is that a page key a package sends must appear in a recorded
request. A `url_pattern` carrying `?page=1&page={page}` satisfies it — the key
`page` is in the capture — while the request actually issued carries the key
**twice**, with a fixed first value the capture never measured in that position.

Servers disagree about which duplicate wins; some take the first, which pins
every page to 1 and returns page 1 N times. That is the duplicate-offer harm
T113's third URL-side route was closed to prevent, reached by a different
spelling.

Found by the second reader on #406 and kept out of that diff deliberately, so
the three routes it did close could be verified on their own.
