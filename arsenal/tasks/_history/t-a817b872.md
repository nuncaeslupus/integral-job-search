`foorilla.com` (which `ai-jobs.net` and `aijobs.net` both 301 to) carries **259,753 live adverts**, is robots-allowed on `/hiring/jobs/`, and has a real `?job_search=` parameter — one of the few boards that searches for a candidate's terms rather than handing over its whole list.

Its listing is served only to an htmx request. Measured 2026-09-06 from a browser capture and reproduced from a cold shell:

| request | answer |
|---|---|
| plain GET | 200, the 10,836-byte shell — no adverts |
| `HX-Request: true` | **400** |
| `HX-Request: true` + `HX-Target: mc_1` | 200, 46,905 bytes, 58 adverts |

No cookie, no CSRF token, no account. The site is public; the request has a shape.

**The rule this relaxes stays.** A connector still cannot name a header — that is what stops an `Authorization` being written into a file, and `names_a_credential` guards the two places free text can appear for the same reason. Instead a connector names a **client** from a closed vocabulary (`htmx`), and every header *name* is a literal in `connectors.py`. The one value crossing the boundary is `client_target`, a DOM element id validated as one — no colon-space, no newline, nothing that could terminate a header and begin another.


## Acceptance gate

```gate
connector_executes_no_shared_code == 1
evidence: status/evidence/T32.json
key: connector_executes_no_shared_code
```

Deliberately the **existing** isolation gate rather than a new one. This task
relaxes the rule that gate protects, so the honest measurement is that the rule
still holds afterwards: every adversarial attempt in
`probe_connector_isolation` is still refused, with the client vocabulary in
place. A new counter of my own would have measured the feature and said nothing
about what it cost.

The narrower properties are pinned by `tests/test_connectors.py`, and the one
that matters is that **no header name can come from a connector file**: a
`client_target` carrying `mc_1: x\r\nAuthorization`, whitespace, a bare
`Authorization: Bearer x`, or an id starting with a digit is refused at load,
and an unknown `client` fails to load rather than silently sending nothing —
which would read to a candidate as "the board returned an empty page".
**4 of 4 mutations caught.**
