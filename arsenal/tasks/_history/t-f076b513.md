Measured over round 3 of the live session: the rule *no salary and no cheap
approximation therefore not shown* removed **13 of 17** survivors. Salary
**silence**, not salary level, is the binding constraint on what a candidate ever
sees.

Two cheap lookups go unattempted before the drop:

1. **The same advert on another board.** `dedup.py` already identifies canonical
   duplicates. If one copy states a band, the silent copy is not silent — the
   figure is one join away and is currently thrown out with the row.
2. **The board's own detail page.** Six HTML connectors leave `salary` unmapped
   because the list page prints one unsplittable string; the detail route often
   does not. The candidate put it plainly: *"If the page says the salary but we
   cannot read it, we need to improve our parsing."*

Beyond that, the candidate accepted an *approximation* as sufficient, provided
it is labelled as one: *"read about that company to give an approximation — this
company usually pays X for this kind of jobs."*

**The failure to avoid is a fabricated band.** An approximation must carry its
provenance and never be stored where `Salary(stated=True)` can pick it up.
`build_offer` already treats any salary key as a statement, so this cannot be
implemented by writing an estimate into the same field — that is the getmanfred
scale bug again, one layer up.
