Filed from a candidate session (test-mode 658fcce2).

`sourcing.source` does `if aim.terms: save_aim(store, aim)` and then searches only `aim.terms[:PHRASE_CEILING]`, reporting the rest as `unsearched`. The only way to search the rest is to call it again with the remaining terms — and that call overwrites the stored aim with the slice. Met on 2026-10-02: a per-board second pass had to re-save the full aim by hand afterwards, and a caller that does not know to do so leaves the candidate with a truncated aim on the next session.

Either `source()` does not write the aim (the step that heard it does), or it takes the full aim plus an offset. One writer for the aim, and a round-trip test: the stored aim after any number of `source()` calls equals the stored aim before.
