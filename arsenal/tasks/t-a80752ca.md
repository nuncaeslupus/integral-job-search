# Payload: t-a80752ca — candidate_root() has no Windows/macOS defaults, and $INTEGRAL_HOME has no backup story

**Gate**: platform-correct defaults via `platformdirs` on Windows/macOS/Linux, `$INTEGRAL_HOME`
still overrides unconditionally on all three, and a backup helper script exists and is executable.

## Tests

- `test_candidate_root_windows_default_uses_platformdirs` in `tests/test_state_home_platforms.py`
  — `$INTEGRAL_HOME`/`$XDG_DATA_HOME` unset, platform mocked `win32`: resolves under the OS-correct
  Windows data dir, not `~/.integral-job-search`.
- `test_candidate_root_macos_default_uses_platformdirs` in `tests/test_state_home_platforms.py`
  — same, mocked `darwin`: resolves under `~/Library/Application Support/integral-job-search`.
- `test_candidate_root_linux_default_unchanged` in `tests/test_state_home_platforms.py`
  — mocked `linux`: matches today's `$XDG_DATA_HOME` / `~/.integral-job-search` chain, no regression.
- `test_candidate_root_integral_home_still_wins` in `tests/test_state_home_platforms.py`
  — `$INTEGRAL_HOME` set: resolves to exactly that path on all three mocked platforms.
- `test_backup_script_exists_and_is_executable` in `tests/test_state_home_platforms.py`
  — `tools/backup_state_home.sh` exists, is executable, `git init`s `$INTEGRAL_HOME` and never
  touches file content already inside `profiles/`.

## References

- Code: `src/integral/state_home.py:205-229` — current `candidate_root()`. The 3-tier priority
  (`$INTEGRAL_HOME` → `$XDG_DATA_HOME` → `$HOME`) must stay identical; only the final
  `~/.integral-job-search` fallback gains real per-OS defaults.
- Deps: `pyproject.toml:6-9` — only `pydantic`/`pyyaml` today; add `platformdirs`.
- Docs: `docs/distribution.md §2` ("Candidate state lives outside the clone") — add a subsection
  on backing up `$INTEGRAL_HOME` as the user's own private git repo. State plainly that this is
  *necessary*, not optional, for any session in an ephemeral cloud container — state is lost when
  the container is reclaimed otherwise.
- Unrelated neighbor: `arsenal/tasks/t-c56152d9.md` (T137) — also touches this area (session-kind
  detection), no expected overlap; re-check after both land.

## Context

Motivated by a real candidate session: a profile made on one machine was invisible from a fresh
cloud session. Two separate gaps, traced together: `profiles/` is correctly kept outside the repo,
but (a) the fallback path has no real per-OS default beyond Linux/XDG, and (b) there is no backup
path at all, which is most acute for ephemeral cloud containers.
