## Where this comes from

The DOMMA application (2026-09-15/16, candidate `vero`). The first letter this
repository generated was fluent, correctly sourced, and rejected by the
candidate in three words: *"suena mucho a Claude."* She then rewrote whole
paragraphs herself, and her drafts carried **the two strongest facts in the
finished application** — that she has *"estat a l'altra banda d'aquesta
conversa"* (she was the buyer the reps pitched to), and the gender-bias
argument about laboratories. Neither was in the store. Neither would have been
elicited by another generation pass, because the skill was not asking; it was
writing.

Five rounds followed, and every round that improved the letter was the same
move: she supplies the sentence, the session edits surgically and says what it
changed. Every round that made it worse was a rewrite in the assistant's
register.

## What to change

`.claude/skills/step-11-application/SKILL.md` currently produces a draft and
invites corrections. Invert it:

- The **first** artefact is a prompt to the candidate, in their own language,
  asking for the letter in their own words — however rough. Not a form, not
  questions with slots. "Write it as if you were telling a friend why you want
  this job."
- What the skill produces from that is an **edit**: the candidate's text with
  named changes, each one a sentence the candidate can veto. Not a new document
  built from the same facts.
- Anything the skill wrote that the candidate did not say is **marked as such**
  in `trazabilidad.md`, so the candidate reads their own letter and knows which
  sentences are not theirs.
- Every sentence the candidate supplies is harvested to the evidence log in the
  same pass (`kind="candidate_statement"`), because a draft is the densest
  source of ground truth the process ever gets — the DOMMA draft carried five
  claims the store did not have.

Register is a step-11 concern, not a style preference: this repository already
requires that every claim trace to a store entry, and a sentence the candidate
would not say is a claim about the candidate that no entry supports.

## What it must not become

A template with the candidate's phrases pasted into it. The test of the rule is
whether the candidate can read the letter aloud without flinching, which is not
checkable by a gate — so what the gate checks is the mechanical half: that the
package records, per paragraph, who wrote it.

## Tests

`test_package_records_authorship_per_paragraph` — a generated package whose
`trazabilidad.md` claims no candidate source for a paragraph fails.

`test_candidate_draft_sentences_reach_the_evidence_log` — statements supplied in
the candidate's draft appear as evidence rows with `source` naming the draft.
