# T70: Robots matching that cannot fail open

## Acceptance gate

```gate
robots_verdicts_misread == 0
evidence: status/evidence/T70.json
key: robots_verdicts_misread
```

```bash
uv run --extra dev pytest tests/test_robots.py -q
uv run --extra dev python -m integral.robots
```

`src/integral/robots.py` must write `status/evidence/T70.json`. This is a new module, so it owns this record outright. **A gate must never name a file no module produces** — the file not existing yet is the honest state of an unstarted task; the file existing but empty of this metric is not.

The `bash` block regenerates it; the `gate` block asserts the number in it.

## Why

`src/integral/robots.py:24` delegates matching to `urllib.robotparser`. Measured on 2026-08-25, it is wrong in both directions:

```text
longest-match:   /jobs/public/x -> False   (RFC 9309 says True)   fails closed
blank-in-record: ClaudeBot /x   -> True    (site said Disallow: /)  fails OPEN
```

The second is the dangerous one. `connectors/trabajos_es/connector.yaml`'s header records that **tecnoempleo.com** and **remoteok.com** were ruled out because their `robots.txt` names `ClaudeBot` with `Disallow: /`. If either file carries a blank line inside that record, our checker currently reports *allowed* — and every `meta.yaml` asserting `robots_txt: respected` is then a false statement shipping to contributors.

## What it must not become

**Do not fix this by post-processing `RobotFileParser`'s answer.** The record grouping is what is wrong, so the parse has already lost the information by the time it returns. Write the matcher. It is ~40 lines: group by `User-agent` (blank lines are whitespace, not terminators), **merge every group whose token equals the crawler's** (RFC 9309 §2.2.1 requires duplicate groups for one token to be combined, not to have the first win), select the most specific token, fall back to `*` only when no explicit token matches, then longest-match with Allow winning ties.

**Failing closed is acceptable where genuinely ambiguous; failing open never is.**

**A zero-violation count over an empty input set is not a pass.** The gate counts
violations, and nothing counted is also zero — so the evidence record must carry
`robots_verdicts_misread_evaluated` (robots.txt fixtures evaluated) and the gate is only meaningful while that count is
non-zero. This is the failure this whole increment is about, turned on its own gates:
a check that reports success over work it did not do. Assert the denominator.

## Tests — write these RED first

`test_a_blank_line_inside_a_record_does_not_end_it` in `tests/test_robots.py` — a `Disallow: /` following a blank line still binds its agent group.

`test_longest_match_wins_over_file_order` — an `Allow: /jobs/public/` beats an earlier `Disallow: /jobs/`, per RFC 9309 §2.2.2.

`test_allow_beats_disallow_on_an_equal_length_tie` — the tie-break direction is Allow.

All three must fail before the fix.

`test_the_gate_does_not_pass_on_an_empty_input_set` — assert `robots_verdicts_misread_evaluated` is written and non-zero.
