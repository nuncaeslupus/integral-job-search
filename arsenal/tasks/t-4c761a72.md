## The defect

`tools/verified_gate.sh:143` prints, in every verdict block it produces:

> CI is unavailable; this is the substitute `CLAUDE.md` names

It is a **hardcoded string**, not a live check. It was true during the runner
outage of 2026-09-04 and false from 2026-09-07, when the repository went public
and Actions became unmetered. Every verdict block pasted onto a pull request
since then has carried a false claim about the state of CI — including blocks
pasted beside a green `CI` check on the same head, minutes apart.

Found independently by two workers on 2026-09-09 while following CLAUDE.md's
instruction to note anything the block misreports, and confirmed at source.

## Why this is not cosmetic

The verdict block exists so that *anyone can see the checking happened*. CLAUDE.md
requires it pasted on the PR and its four results quoted in the merge commit,
precisely because "a merge whose evidence lives in one session's scrollback is a
merge nobody can audit afterwards."

A block that asserts something false about CI is an **evidence artefact that
reports a condition it did not measure** — the repository's own named defect
family, in the one file whose entire job is to be trustworthy about what was
measured. It is also the exact failure mode CLAUDE.md's § *Known environment
state* warns about and has committed three times: a recorded environment fact
that was true when written, went stale, and kept being asserted.

## What the fix has to do

The block must either **measure** what it says about CI, or **say nothing** about
it. A line that cannot be wrong is better than one that is currently wrong:
`verified_gate.sh` measures the committed commit and CI measures the merge ref,
which is the complementarity CLAUDE.md already describes — the block can state
its own scope without making any claim about the other half.

If it does report CI, it must report what it read, with the clock test
CLAUDE.md gives (a whole run under ~10 seconds with unreadable logs is a runner
dying; a run of a minute or more is a verdict), and it must degrade to "not
checked" rather than to a claim.

## What the metric counts

`verdict_block_claims_about_ci_that_are_not_measured` is the number of
assertions the emitted block makes about CI's availability or result that the
script did not derive from an observation in that same run.

It must be **behavioural**, in `integral.verified_gate`'s established idiom: that
module already refuses to read the script's text, because three rounds of pattern
matching were defeated by comments, an unused single-quoted string, and trailing
comments. Run the script against a throwaway repository and read the block it
emits — do not grep the source for the sentence.

The contracts asserted are the denominator, committed as a **literal floor**
(T100/T122 style), never derived from the count of contracts found.

**Verify the metric is non-zero against today's tree before writing the fix** —
it should find at least the one assertion above.
