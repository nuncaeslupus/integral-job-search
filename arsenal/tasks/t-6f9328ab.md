Found while opening PR #89 (2026-08-20).

`CLAUDE.md` says all five must pass before a merge:

    make lint  test  evidence  verify-subtree  verify-gates

Nothing runs them. Three separate holes, and PR #89 fell through all three:

1. **CI cannot.** GitHub Actions has been out of runner minutes since 2026-08-19 —
   every job on every run fails in 3-5s with `runner_id: 0`, `main` included. So
   `ci.yml` is not an enforcement point today, and `arsenal-queue.yml` is not either,
   which also means the `task-file-landed` hook that opens issue handles never fires.
2. **`open_task_pr.sh` runs the wrong gate.** A worker re-runs `gate_run.sh` on its own
   payload. Nothing in that path runs the repo suite, so a worker can open a green task
   PR that breaks `make test`.
3. **`keyword-guard` only fires on `arsenal/**` branches.** PR #89 was on
   `s12-test-session-findings`, so no check ran on it at all.

The five ran only because a human asked. `make test` then failed on nine title-label
violations that would otherwise have merged.

The fix is an enforcement point that does not depend on runner minutes: a pre-push or
pre-merge hook in the repo, or a `make gate` target that `open_task_pr.sh` calls before it
pushes, with the run recorded so a merge can be refused when it is absent. Prose in
`CLAUDE.md` is not one.

Addressed in: `Makefile`, `claude-arsenal/bin/open_task_pr.sh`, `.github/workflows/`.
