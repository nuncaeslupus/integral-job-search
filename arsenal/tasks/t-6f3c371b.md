## Context

Found on T194 (#520). The script reported `standing: single_parser` — "the reader ran and
could not refuse" — for `es.talent.com`. That was the right answer *before* T120: CPython's
`robotparser` returns the first matching rule rather than RFC 9309's longest match, so on
any file opening `Allow: /` it cannot refuse, and the skill's own text says an agreement
with a parser that cannot disagree is not an agreement.

It is the wrong answer now. On the same bytes, the installed reader refuses
`/search-jobs/python` and `/ajax/x` and the correct standing is `two_parsers_agreed`. The
row shipped correct because the session re-derived it by hand; a session that trusted the
script would have recorded a weaker standing than the evidence supports.

Note the direction: this one is fail-*closed* — it understates. That is why it survived.
It is still a script whose verdict is a version behind the repo it probes for, and the
next reader swap moves it again unless it resolves the reader rather than naming one.
