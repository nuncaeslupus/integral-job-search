### Finding
`_one_board` pauses `robots.delay(url, 0.0)` between list requests and before each advert page, so for a host with no Crawl-delay the 56 Greenhouse boards, 57 Ashby boards and up to 40 detail pages per board go out back-to-back. That contradicts the README's 'Polite sourcing' and the 1.0 s floor the same repo uses in canonical_ad and tools/collect_ads, and invites a 429 that then marks the whole origin refused for the run.

### Evidence
Traced the loop; employer counts from `yaml.safe_load` of connectors/*/connector.yaml (greenhouse 56, ashby 57, lever 13); DETAIL_FETCH_CEILING = 40; canonical_ad.DEFAULT_DELAY_FLOOR = 1.0, collect_ads uses POLITENESS_FLOOR.

### Suggested direction
Use one shared per-origin floor (>= 1 s) for list and detail requests, tracked per origin rather than per `index`.
