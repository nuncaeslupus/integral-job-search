`src/integral/eligibility.py` must write `status/evidence/T78.json`. This is a new module, so it owns this record outright. **A gate must never name a file no module produces** — the file not existing yet is the honest state of an unstarted task; the file existing but empty of this metric is not.

The `bash` block regenerates it; the `gate` block asserts the number in it.

## Why

**Settled by the owner on 2026-08-25:** the language gate gets its own hard field rather than reading `dimensions/english_demand.yaml`.

The dimension is a soft, scored preference the ranker weights. The gate is a hard filter. Merging them would let a preference weight cancel a legal or linguistic bar — a failure that would be **invisible in any output either layer produces**, which is exactly why the boundary is pinned by tests rather than by a comment.

`offer.language_requirement` records `{language, level_stated, quote, applies_to}` and is read only by the gate. See `status/spec-v3-silent-success.md` §5.1 and §5.3.

## What it must not become

The distinction that is easy to get wrong: read the language requirement **stated for the role**, not the language the advert happens to be written in. A Catalan advert for a role needing only Spanish demands Spanish.

The boundary test must fail in **both** directions — ranker reading a gate field, and gate reading a weight.

**A zero-violation count over an empty input set is not a pass.** The gate counts
violations, and nothing counted is also zero — so the evidence record must carry
`gate_fields_read_by_the_ranker_evaluated` (gate/ranker field reads audited) and the gate is only meaningful while that count is
non-zero. This is the failure this whole increment is about, turned on its own gates:
a check that reports success over work it did not do. Assert the denominator.
