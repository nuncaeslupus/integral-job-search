### Finding
The PreToolUse guard finds Bash paths with the literal regex `profiles/[\w.-]+…`, so `cd <root>/profiles && cat bob/cv.json`, `cat <root>/prof*/bob/cv.json` and `grep -r salary <root>` are all allowed while another candidate is active; and the hook matcher is `Read|Write|Edit|NotebookEdit|Bash`, so Grep, Glob and MultiEdit calls into another profile are never checked even though `guard_tool_call` would refuse them.

### Evidence
Repro: guard_tool_call('Bash', {'command': …}, root, active='alice') returns allowed=False for `cat $D/profiles/bob/cv.json` but True for the cd, glob and `grep -r` variants; guard_tool_call('Grep', {'path': root/'bob'}) returns False, but 'Grep' is not in the settings matcher.

### Suggested direction
Add Grep|Glob|MultiEdit to the matcher, and for Bash refuse any command that mentions the profiles root (or its parent) unless every path under it resolves to the active handle; state in README that the guard is an accident barrier, not isolation.
