Imported from issue #747

Follow-up from the second-reader rounds on #746 (T207, step-00 profile opening). These were deferred as non-blocking.

- **L1: look-alike display names.** Twins whose names differ only by confusable characters (Cyrillic `Аna`, fullwidth, a zero-width space) are not detected as collisions. A yes can then open the wrong profile, and the same-day `ambiguous` check is escaped. `main` already behaves this way. A fix needs a confusables skeleton (UTS #39) or a refusal of mixed scripts in display names.
- **L3: accent-insensitive names.** `--name nuria` for a profile named "Núria" returns `create` ("no profile yet"). This fails closed, but the wording is misleading.
- **L5: `--confirmed` is stateless.** Passed on the first call, it opens without the question having been asked, the same as `main`'s `resolve_handle(confirmed=True)`. Only the SKILL text enforces the order.
- A unique profile whose `created_at` cannot be parsed fails closed on `--handle` but still opens via `--name`. That is acceptable, and noted here for consistency.
