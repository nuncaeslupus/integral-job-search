Imported from issue #657

Found by the second reader on #655, and pre-existing on `main`.

- **Fail-open:** if `profiles/.active.json` holds non-UTF-8 bytes, `read_active_handle` raises `UnicodeDecodeError`. Its `except (FileNotFoundError, JSONDecodeError, OSError)` does not catch that, so `tools/profile_guard.sh` exits **1**. A PreToolUse exit other than 0 or 2 is non-blocking, so the guarded call proceeds. Because any session may write roster metadata, one bad write turns off the guard for every session.
- **Low impact:** a NUL byte in `file_path` raises `ValueError: embedded null byte` from `resolve()`, which also exits 1.

**Fix:** treat an unreadable marker as no marker (catch `UnicodeDecodeError`/`ValueError`), and wrap `hook_main` so that any exception while judging a call ends in exit 2 (fail closed). Commit fixtures that drive both inputs through `tools/profile_guard.sh` and assert exit 2.
