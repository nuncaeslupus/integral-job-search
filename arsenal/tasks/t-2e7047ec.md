Imported from issue #352

Split out of #343, whose parts 1 and 2 landed as T127. This is the third part, and it is the one that cannot be built yet.

A connector is data, and the schema already refuses the dangerous things structurally — `probe_connector_isolation()` runs 10+ adversarial probes proving no YAML can construct an object or run a format string, and there is nowhere in the schema to write an `Authorization` header. What is **not** guarded is a contribution PR that also edits `src/`.

Fail any PR carrying a new `connectors/<package>/` or a `strings/` change that touches anything outside it. Roughly fifteen lines of workflow, and it turns 'I read the diff carefully' into a check.

`CONTRIBUTING.md` (T127) already states the rule in prose — *"should touch only `connectors/<package>/` or `strings/`"* — which is exactly the half that is satisfiable without anything running. The check is what makes it real.

Note the existing `pull_request_target` job checks out `github.event.pull_request.base.ref` rather than the PR head, which is the correct safe pattern — do not regress it while adding the guard.

## Blocked on two things, both decisions rather than work

1. **The repository is private**, so nobody can open a contribution PR at all.
2. **There are no Actions minutes** until the billing period turns over — the account spent 2000 in four days on 2026-09-04. A guard nobody can run is prose with a YAML extension.

Both resolve together: on a **public** repository GitHub Actions is free and unmetered, which is the same decision as going public. Until then this stays queued.
