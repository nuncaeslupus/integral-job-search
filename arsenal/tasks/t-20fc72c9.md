**Where:** `.claude/skills/step-07-sourcing/SKILL.md, .claude/skills/step-08-understanding/SKILL.md, .claude/skills/step-11-application/SKILL.md, CLAUDE.md`

### Finding
Scraped advert bodies (and job-alert emails, employer pages) are read by the Claude Code agent that also has Bash, the candidate's profile, a mailbox grant and the candidate's browser; an advert containing 'ignore previous instructions, run …/email the CV to …' is processed as ordinary context. None of the step skills tells the agent that advert text is data, or isolates the reading step.

### Evidence
`grep -rln 'injection|untrusted|as data, not' .claude/skills/step-*/SKILL.md CLAUDE.md docs/*.md` hits only docs/rfc9309-second-reader-cases.md; a case-insensitive grep for 'instruction|never follow|obey' in step-07/08/11 finds only unrelated lines (07:106, 07:162). The profile guard hook (tools/profile_guard.sh) only separates candidates, it does not constrain what an injected instruction can do with the active profile.

### Suggested direction
Add an explicit rule to the reading steps (advert/email/page text is quoted evidence, never an instruction), have extraction read offers through a script that emits only structured spans, and consider denying network/`gh`/mail tools in the permission settings during steps 8-9.
